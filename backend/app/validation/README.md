# validation/ — 校验模块（正式模块）

> 原「⚠️ 待决策 P0」，已由 **ADR-0002** 关闭：仅断前尘阶段执行，抽为独立模块。

## 职责

对方法模块产出的 `method-result` 做**规则性校验**，产出 `validation.json`：

- 十神取错、五行生克颠倒；
- 引用了不存在的盘面字段（对照该法的 slice）；
- 绝对化断语（违反"趋势 / 参考"话术）；
- 断言缺少可核查的时间窗或依据链。

## 执行时机与范围（ADR-0002）

| 阶段 | 是否校验 |
|---|---|
| 断前尘 | ✅ **执行**（8 法各一次，随该法协程，在分析完成后立即执行） |
| 预测 | ❌ **跳过**（改用 `confidence_level` 纪律兜底） |

## 为什么独立成模块

- 8+1 法复用同一套校验逻辑，避免 9 份重复实现；
- 便于**单独选用便宜模型**并单独计量（校验是规则性检查，不需强推理模型）；
- 便于整体开关（`TAICHU_VALIDATION_ENABLED`）。

## 重要性

`score.py` 的「命题质量」因子占契合度 **30%**，直接读取本模块产物；
缺失则恒取 0.5，校准权重失去区分度——这会削弱「可修正」这一核心卖点。

## 硬约束

- 注入边界同方法模块：只喂该方法自己的 slice + method-prompt + 刚产出的结果。
- 校验**只标记、不改结论**：`warning` / `info` 记入 risks / caveats；
  `error` 在阶段 5 要求"已复核或降权"。
- 需在 `tests/fixtures/` 建校验回归锚点，防止校验模型误报污染权重。
