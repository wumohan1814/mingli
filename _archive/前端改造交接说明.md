# 太初前端改造交接说明（面向研发）

> 背景：用户指出「存在两套前端，且运行的不是我以为的那套」后，对真正生效的前端做了系统性改造与合并。本文供研发团队知悉现状、契约与未决项。

---

## 0. TL;DR（一句话）

- **真正运行的前端是 `frontend/public/index.html`**（FastAPI 通过 `StaticFiles` 直接托管它），不是 `frontend/src/`。
- 它是**免构建**形态：CDN/OSS 的 React 18 + Babel Standalone 运行时编译 JSX，**不是** Vite/TS 工程编译产物。
- 文档已拍板走「免构建」路线，**不重启 Vite**（沙箱此前也阻断了 Vite/esbuild，从未成功构建过 `src/`）。
- 所有生产改动都落在 `index.html`；`src/` 仅作为参考源码被**同步修正到一致**，未来若要「源码即运行件」需先解决沙箱 Vite 限制。

---

## 1. 两套前端的真实状态（关键事实纠正）

| 路径 | 状态 | 说明 |
|---|---|---|
| `frontend/public/index.html` | ✅ **实际生效** | FastAPI `main.py` 里 `app.mount("/", StaticFiles(directory=.../frontend/public))` 直接服务。CDN React + Babel Standalone，当前 8 页。 |
| `frontend/src/` | ⚠️ 不参与运行 | Vite + TS + antd-mobile 源码（8 页），但沙箱阻断 Vite/esbuild，**从未构建**；多数页面为 8–21 行占位；`api.ts` 的 `unwrap(res.data.data)` 与后端真实返回不匹配。 |

**结论**：研发若要对接/继续开发，应以 `frontend/public/index.html` 为权威对象。

## 2. 后端契约事实（研发必读，已逐项核对源码）

### 2.1 两种响应信封并存 —— ⚠️ 切勿统一 unwrap
- **`/auth/*`（register / login）**：返回**裸对象** `{ access_token, refresh_token }`，**非信封**。
- **`/cases`、`/jobs`**：返回信封 `{ code, data, meta }`。
- 因此前端的请求层必须**逐接口处理**，不能写一处 `res.data.data` 统一解包（旧 `src/services/api.ts` 的 `unwrap` 正是这个 bug，已修）。

### 2.2 建档字段
- `CreateCaseRequest` 含 `longitude / latitude / true_solar_time`。
- 排盘引擎依赖经纬度才能算**占星 / 七政 / 奇门 / 五运六气**四法；缺经纬度时这四法端到端降级（实测 `degradedMethods=['qimen-lifetime','western','qizheng','wuyun-liuqi']`），「九法综合」实际只剩 5 法。

### 2.3 档案接口
- `GET /api/cases/{id}/archive` → `{ data: { caseId, input, status } }`，`input` 即建档时全部字段（含经纬度/真太阳时）。

### 2.4 任务状态枚举
- `JobStatus`：`pending / running / succeeded / failed`。失败态判定用 `status === 'failed'`。
- 硬超时约定（技术框架 §5.1）：断前尘 **10min**、预测 **3min**。

## 3. 已完成的改造（按优先级）

### P0 — 功能正确性 / 合规（已补）
1. **建档表单补经纬度 + 真太阳时**：新增经度/纬度双列输入（可选）+ 内置 36 城坐标表（出生地命中自动填充，可手动覆盖）+ 真太阳时开关；提交时经纬度为空则发 `null`，四流派不再必然降级。
2. **新增档案页 `ArchivePage`**：接入 `archive` 路由，预测/追问页加「我的档案」入口；调用 `GET /cases/{id}/archive`，渲染建档信息+状态，无经纬度时显降级提示。
3. **全局末行免责**：新增 `DisclaimerFooter` 在每页底部常驻（硬编码朱砂 `var(--cinnabar)` 跨皮肤合规标记），移除 landing/predict 内联重复项，满足「末行免责必须存在」。
4. **校准「修正 ✎」收集文本**：改为先弹 `textarea` 收集 `user_note`，随 feedback 以 `{ feedback:'corrected', user_note }` 提交（对应技术框架 §5.4 质疑库 `user_note`）。

### P1 — 健壮性 / 登录态（已补）
1. **失败态 UI**：`WaitingPage` / `PredictPage` 新增 `failed`、网络异常、`catch` 空捕获修复，以及硬超时（10min/3min）的失败页（错误提示 + 重试 + 返回），用 `useRef` 管 timer/timeout 防竞态。
2. **登录态完整**：存 `refresh_token`；`api()` 遇 401 自动清 token 跳登录；App 挂载若有 token 自动跳 onboarding；预测/追问/档案页加「退出登录」。
3. **表单范围校验**：年 1900–2100 / 月 1–12 / 日 1–31 / 时 0–23，非法拦截并提示（避免 `lunar-python` 抛 500）。

## 5. CDN 本地化 + 图标/动效精致化

### 5.1 CDN 本地化（消除白屏风险）
- 将 `react@18` / `react-dom@18` / `@babel/standalone` 落盘到 **`frontend/public/vendor/`**（react 11KB / react-dom 132KB / babel 3.14MB，头部校验正常）。
- `index.html` 的三个 `<script src>` 由 `https://unpkg.com/...` 改为 `./vendor/...` 本地相对路径 —— **彻底消除香港/国内节点因 unpkg 不稳导致的白屏**。
- 注：Google Fonts 链接保留（字体失败有系统衬线/黑体回退，非白屏风险点；CJK 字体内嵌会膨胀数 MB，故未强行自托管）。

### 5.2 图标精致化
- 新增内联 SVG `Icon` 组件：九法点阵 / 铅笔 / 对话 / 升·降·平 / 勾·叉 / 星印 / 轨道，全部 `currentColor` 随皮肤自适应。
- 替换全部 Unicode 字符（☰✎◎☷✶ 等）：landing 三卡、免责星印、校准三按钮、predict 总览与趋势。

### 5.3 动效精致化
- **骨架屏** `.skeleton`（shimmer 流光），用于 PredictPage / ArchivePage 加载态。
- **页面切换过渡** `.view-enter`（`key={page}` 触发重挂载，淡入上移）。
- 卡片/主按钮 hover 微交互。

## 6. 给研发的须知 / 未决项

- **权威运行件**：`frontend/public/index.html` + `frontend/public/vendor/`（自包含，断网可渲染）。
- **双信封**：`/auth/*` 裸 `{access_token,refresh_token}` vs `/cases`、`/jobs` 的 `{code,data,meta}`，**新页面别统一 unwrap**。
- **MVP 仅国学皮肤可切**，占星/塔罗置灰（Phase 2 后端支撑）。
- **predict 报告仍是 mock**（技术框架既定 Phase 4 才接真实 LLM），非缺口，但需标注。
- **经纬度"自动解析"采用内置城市坐标表**（离线、无外部依赖），非实时地理编码 API——若想要实时检索可换。
- `src/` 若要成为真正可运行件，需先解决沙箱 Vite/esbuild 限制，再把已验证的 8 页逻辑端口为 `src/pages` + `src/components`（接 `tokens.css`）。
- 校验方式：本地 `@babel/core` + `@babel/preset-react` 对 `<script type="text/babel">` 做 `transformSync` 转译通过（无语法错误）+ 结构 grep 确认各项落地。
