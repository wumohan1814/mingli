## 二、经验清单（按踩坑代价降序）

### 1. 架构设计（代价最高：返工/重做/成本失真）

**A1 新库冲动 vs 仓库现成资产**
- 现象 → 需求方提出用 5 个外部库实现新模块；盘点后发现仓库已 vendored 的 `mingyu-core` 含全部所需引擎（塔罗/生肖/占星推运/起卦）+ 中文文案。
- 根因 → 对外部生态的熟悉度 > 对仓库内嵌资产的熟悉度；没先读依赖的 barrel/入口文件。
- 规则 → 选库前先盘点「已在仓库里的能力」；外部库只按**增量缺口**引入，差集为空则跳过并留档理由。
- 检查项 → □ 列出现有依赖能力清单 □ 每个候选库标注与现成的差集 □ 跳过的库写理由。

**A2 LLM 用量 = 单位经济；确定性计算先行**
- 现象 → 同类产品算与生成分离的成本差可达 10 倍；本 session 每个模块都先拆「确定性层 / LLM 层」。
- 根因 → LLM = token = 钱 + 延迟；排盘/抽牌/起卦/计分本质是纯计算 + 可复用文案。
- 规则 → 每个 feature 强制先答「能否确定性计算 + 内置中文文案」；LLM 只保留「把确定事实串成解读」一步，且做成**可选付费**。
- 检查项 → □ 是否有确定性方案段落 □ 每个 LLM 调用点接 usage 账本与扣费 □ 免费层覆盖完整体验主链。

**A3 成本口径必须含「辅助 LLM 调用」（ADR-0002 实证）**
- 现象 → 校验曾被整体省略 → 成本闸门失真约 2 倍、质量因子恒取 0.5。
- 根因 → 只把主分析计入模型，漏算校验等伴随调用。
- 规则 → cost model 第一天就把**全部** LLM 调用类型纳入计量并分开配档；契约枚举（domain/confidence）先冻结。
- 检查项 → □ 每 phase 的 LLM 调用数有书面口径 □ 便宜模型档位有切换点 □ 单 case 成本阈值由实测回填。

**A4 进程模型：常驻服务 + 保真降级链**
- 现象 → 每次 subprocess 起 Node 排盘内存峰值高；改常驻 HTTP（1 进程 ~100MB）+ subprocess 降级。
- 根因 → 每请求冷启动 = N 倍内存/延迟。
- 规则 → 高复用重库走常驻；保留降级路径；分层各自容错，「正确性优先、不阻断主链」。
- 检查项 → □ 重复加载的重依赖是否已常驻化 □ 降级路径是否字节级保真 □ 任一层失败自动回退并告警。

**A5 单一事实源：权威运行件/文档必须显式指定**
- 现象 → 前端两套（`index.html` 运行 vs `src/` 参考，文档曾与事实相反）；版本记录描述 0.3/0.4 已实现而代码不存在、引用文件缺失。
- 根因 → 事实源未指定，文档互相矛盾且无人交叉验证。
- 规则 → 任何「形态/状态」只允许一个权威声明；交接时给「权威清单」并逐项核对文件/commit 存在性；发现冲突当场标「以 X 为准」。
- 检查项 → □ 权威运行件写入文档 □ 文档引用的表/文件是否实际存在 □ 冲突显式裁决而非静默。

**A6 长任务四件套：轮询态 / 幂等 / 续跑 / 子步计量**
- 现象 → 异步化后出现重复触发重复扣费风险 → jobId+轮询+幂等复用+断点续跑+逐法扣费。
- 根因 → 长任务无幂等键、无中断恢复语义。
- 规则 → 长任务必有：可轮询状态、进行中任务复用、重启后可恢复（已完成子步零成本复用）、按子步计量。
- 检查项 → □ 重复点击只建一个任务 □ 孤儿任务有失败/恢复语义 □ 已成功子步重跑不重复扣费。

### 2. 协作协议（代价中：churn/返工/错位）

**B1 交付物末尾固定「带默认建议的待确认单」**
- 现象 → 首轮即问 4 项开放问题（盘型/美术/MBTI 源/付费点）；用户逐条答，同时**夹带新需求**（HUB 页、起卦用档案）。
- 根因 → 用户偏好增量决策；问题不带推荐项时决策成本高，且回答常扩展 scope。
- 规则 → 每个决策点给「默认建议 + 后果」供确认/否决；用户回复后先 diff「新增了什么、改了哪些旧结论」再动文档。
- 检查项 → □ 开放问题都带推荐项 □ 回复后先 diff 再落文档。

**B2 高 churn 期不要过早固化编号文档**
- 现象 → 三份文档因需求两次大改（入口 4→3+双 HUB；星座塔罗并西式；首页弃浮动胶囊）连续重排章节号与交叉引用。
- 根因 → 结构未稳定就落成正式编号长文档，每次澄清产生整文 churn。
- 规则 → 需求震荡期用「单页结论清单」交流；连续 ≥2 轮无结构变化再固化编号文档；逻辑方案与 UI 方案分文件隔离。
- 检查项 → □ 最近两轮是否改了入口/导航结构 □ 未稳定则不承诺章节编号 □ 交叉引用指向「稳定结论」而非章节号。

**B3 共享工作区 = 跨 session 唯一记忆，交接文档模板化**
- 现象 → 项目靠 `Session交接文档`（状态快照/待办/决策/运维勿回滚）跨 session 延续。
- 根因 → 会话上下文不跨 session，只有落盘可传。
- 规则 → 每 session 结束更新「状态快照 + 待办(带 owner) + 勿回滚护栏」；新 session 先读交接再动手。
- 检查项 → □ 结束前更新交接 □ 待办标 owner □ 护栏单独一节。

**B4 外部依赖先验证可信性**
- 现象 → 检索命中的仓库与用户给链接不符（miyaosk/mbti-test-skill 疑似 404）。
- 根因 → 链接/仓库名易过时或同名异仓。
- 规则 → 外部依赖写进方案前验证存在性/维护/license；不可及就以「机制自研 + 内容多源改写」兜底。
- 检查项 → □ 链接可访问 □ license 允许复制/改写 □ 有零依赖兜底方案。

### 3. 工作定义（代价中低但高频叠加：返工主因）

**C1 启动即定义「不做清单 + 约束决策表」**
- 现象 → 本 session 用决策表 D1–D8（引擎/盘型/付费/LLM 边界）冻结前提；后续需求与决策表对照推进。
- 根因 → 无约束表时新需求会悄悄推翻旧前提。
- 规则 → 验收/禁止/边界写成决策表；新需求先对照，冲突则显式修订而非悄悄改。
- 检查项 → □ 决策表含引擎/范围/付费/合规 □ 冲突有修订流程。

**C2 里程碑 = 可勾选闭环 + 四层测试**
- 现象 → 工作拆成 Phase A–D，每阶段含「确定性端点→可选 LLM→UI→文案→埋点→测试」可勾选项。
- 根因 → 大目标不可验收；返工源于「没定义完成」。
- 规则 → 每阶段最小可独立验证闭环；单测/集成/端到端/回归四层。
- 检查项 → □ 每里程碑可独立上线验证 □ 含回归（不破坏旧链）□ owner/阻塞标清。

**C3 角色与决策权分离（owner 模式）**
- 现象 → self-run 成本实测 owner=用户；塔罗美术用户另行生成，agent 只做占位与装配规范。
- 根因 → 决策权在用户侧的项目，agent 代跑会白做。
- 规则 → 动工前问清「用户拍板项 / agent 自主项」；用户决策项的默认动作 = 出方案占位等确认。
- 检查项 → □ 每开放项有 owner □ agent 自主边界明确 □ 阻塞项显式挂起并记录。

**C4 小步交付 + 三行小结锚点（支持中断/恢复）**
- 现象 → 本 session 多次被打断（省 token、增量澄清），靠每轮结论续做。
- 根因 → 无恢复锚点则重读上下文成本高。
- 规则 → 每个交付 1–2 段方案 + 默认建议，自包含可评审；轮尾留「当前结论/待办/待确认」三行。
- 检查项 → □ 轮尾三行小结 □ 恢复时不重读全文即可接上。

### 其他（工具级，低代价高频）

**O1 大文件整写失败要先重读再重试**
- 现象（本 session）→ 整文件 write 两次失败（EIO / file changed since read）。
- 根因 → 大文件整写与变更检测/IO 易冲突。
- 规则 → 大改动优先定向 edit；整写失败先重读再重试，勿盲目重发。
- 检查项 → □ 大改动用 edit □ 失败后重读→重试。
