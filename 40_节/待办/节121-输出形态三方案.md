## 三个方案的完整形态与实现路径（转方向时的参考）

### 甲 · 不打分（**已选 · 2026-09-11**）
- **输出形态**：`吉/凶/平` + `confidence_level` + **分歧标注**；多法一致时标"多路同指"并允许**上调置信度**
- **实现路径**：
  - 契约层：`backend/app/methods/base.py` L11-17 的 `method-result v2` **已含** `direction` + `confidence_level` + `evidence` + `risks` + `basis` → **零契约改动**
  - 裁决层：`backend/app/synthesis/synthesizer.py` —— 需重建 `_decide_trend()`（现状是**纯计数多数决**，L37-44 / L115-125），改为"**主/辅法权重 + 置信度聚合 + 分歧标注**"（即 **节116** 的活）
  - 表达层：提示词规则 + 报告 8 板块的**分歧并列**写法
- **落地节**：**节116**（综合裁决与置信度）
- **代价**：解读里会**出现"两法看法不同"这类表述** → 需要产品能接受"不装权威"的语气
- **风险**：用户可能觉得"没给准话" → 用**分档**缓解（见丙）

### 乙 · 打分（**未选**）
- **输出形态**：1–100 分或百分比，形如「财富 **72** 分（理论天花板 90 × 现实预期 0.8）」
- **实现路径**（若将来要转）：
  1. **定义分数口径**（最难的一步，且必须能自圆其说）：分层 = `理论天花板分 × 现实预期系数 × 环境系数`（参考 `mingyu-skill-main` `SKILL.md` L66-74）
  2. **契约层**：需给 `method-result v2` **新增分数字段** → ⚠️ **单向门**（`00_根/入口.md` 红线④"method-result v2 / chart.json 契约"），**必须走"记决策 + 声明影响范围 + 检查既有引用"**（破竹 §6 触发即留痕）
  3. **裁决层**：把多法结论**聚合为单一分数**（与节116"分歧标注"**互斥** → 二者只能选一个）
  4. **表达层**：分数 + 档位文字 + 免责；**必须防"伪精确"**（否则违反 `mingyu-main` 产品红线，也违反命理"末行免责"取向）
- **落地节建议**：**单独立节**（"财富分层与打分口径"），因为它要定义一套**设计值**（天花板分/系数），属 `00_根/复用.md` 的"设计值"范畴
- **好处**：**可比较、有传播性**（用户会截图分享）；**坏处**：①把解读不确定性伪装成计算精确性 ②分数口径无法被证伪 ③与"分歧标注"路线互斥，**等于推翻节116 的方向**

### 丙 · 只给分档不给分数（**折中 · Agent 原建议**）
- **输出形态**：用**有序档位**替代伪精确数字 —— 如「财富层级：**中上（共 5 档）**」+ **仍保留分歧标注**
- **实现路径**：
  1. 定义 **3–5 档的东西**（如 财富/事业/婚姻 各 5 档），档位**名称用大白话**（不适合用"上上/中平"这类术语）
  2. 档位判定**复用甲的裁决层**（节116）——档位 = `direction` + 强度/幅度，**不新增契约字段**，只在**渲染层**把"吉/凶 + 幅度"映射成档位文字
  3. **不进入 `method-result v2`**（档位是**展示层**概念，不是契约层概念）→ **绕开单向门**
- **落地节建议**：可作为 **节116 的后续小项**（渲染层），**不需独立大节**
- **好处**：**既能比较又不过度承诺**；**正好卡在"排盘能算准 / 解读算不准"这条线上**
- **坏处**：档位边界仍需定义（但比分数口径**容易自圆其说**得多）
