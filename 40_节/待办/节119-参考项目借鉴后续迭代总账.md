# §7 太初侧核对（清点副产物 · 三项潜在正确性缺陷 · 全部已核实）

> **起因**：参考项目**三处独立**指向"真太阳时"与"中国 1986–1991 夏令时"必须处理（bazi `排盘工具集成.md` / HCM `onboarding.md` L29-34 / mingyu-main `chinaDst.ts`+`trueSolarTime.ts`+`paipanWarnings.ts`）。核对太初现状如下 —— **结论：三处都是真实缺口。**

## N1 · 真太阳时：**默认关闭**，且只做经度项、**缺均时差**（已核实）
证据 `backend/app/paipan/engine.py`：
| 位置 | 事实 |
|---|---|
| **L328** | `true_solar: bool = False` ← **默认关闭** |
| **L343** | 注释自述"真太阳时**近似**" |
| **L347-352** | 只算 `delta_min = int(round((longitude - 120) * 4))` → **只有经度项，没有均时差（equation of time，可达 ±15 分钟）** |
| **无跨界处理** | 修正后的 `hour/minutes` **直接进排盘**，没有"是否跨过时辰边界"的检测或提示 |
| 调用方 | `backend/app/api/cases.py` L201、`api/case_share.py` L95 默认同样 `False` |
| ✅ 好的部分 | `true_solar_applied` 落进盘面（L409 / L412），**留了痕**（这一点比参考项目还细） |

**风险量化**：经度项最大偏差 ≈ ±(120−74)×4 ≈ **±184 分钟**（新疆）；均时差再叠加 **±15 分钟**。→ 未开真太阳时 + 无均时差，在**西部出生地**会显著提高「时柱错位」概率（参考项目给出的口径是"可差 **0.5–1.5 小时**"）。

## N2 · 中国 1986–1991 夏令时：**完全没有处理**（全库零命中）
证据：`夏令时 / dst / daylight` 在 `backend/app/` grep **零命中**；`engine.py` L354 直接 `Solar.fromYmdHms(year, month, day, hour, minute, 0)` 使用**用户输入的钟表时间**，无任何 DST 校正。
**影响**：1986–1991 年（每年 4 月中–9 月中）出生者，钟表时间比标准时间**快 1 小时** → **时柱可能整体错一位**，进而影响时柱相关的**全部**结论（子女宫 / 晚年运 / 部分格局 / 紫微命宫）。
**受影响人群**：1986–1991 年出生者现约 **35–40 岁**，正是命理消费主力年龄段之一。
**判定**：**真实、人群明确、可量化**的正确性缺陷 → **优先级高于本清单里绝大多数优化项**。

## N3 · 缺「输入层不确定性」的对外声明出口（有技术层，缺信息层）
太初**已有** `meta.degraded_methods`（`engine.py` L384-396 / L404），但它记录的是「**哪些法没跑出来**」= **技术层降级**（ziwei / western / qizheng / wuyun-liuqi / bazi-hour / qimen-lifetime）。
**缺的是「信息层不确定性」**：
- 真太阳时**未应用**（用户看不出自己的盘没校正）
- 出生时辰为**估计值** / 时柱**缺失**
- 日柱**未交叉验证**
- 出生时间落在**时辰边界附近**（口径敏感）
参考项目对应物：`mingyu-main/packages/core/src/bazi/paipanWarnings.ts`、HCM `docs/onboarding.md` L27 / L48（标注「置信度：时辰估计」「时柱缺失」「日柱未交叉验证」）。
→ 这正是节116「置信度聚合」的**上游缺口**：**输入不精确不该只体现在最终 confidence，应显式告知用户**。
