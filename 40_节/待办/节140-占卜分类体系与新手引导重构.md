## 〇、方向决策（2026-09-12 讨论）

**用户拍板：走方向丁（大区 + 多维标签）**，理由：同一方法可挂多个标签出现在不同分类中；同时采纳丙的「新人零门槛」作为默认进门方式。印度/泰国仅为扩展性举例，**现在不开空区**，有真实功能再露面。

**用户要求的双模式**：
- 新手引导模式（默认开）：新用户先选大类（白话问题分流）→ 进入后罗列相关占卜方式，**从简单上手到复杂排序**
- 老手模式（开关关闭）：跳过引导，直接用标签筛选占卜方式，更快
- 开关可由用户自行切换

### 丁方案细化（2026-09-12 第一轮设计，待用户确认细节）

**大区（骨架）**：现阶段仅 3 个——中华术数 / 西方占卜 / 心理测试。大区语义 = 「功能数最多的文化圈提升为一级」，非写死；未来印度系功能进场先打标签，数量够了再提升大区。

**标签维度（每法一张「身份证」，均多选）**：
| 维度 | 值 |
|---|---|
| 回答什么 | 看一生格局 / 问当下事 / 看流年运势 / 择吉取名 / 双人关系 |
| 怎么玩 | 生辰排盘 / 摇卦起课 / 抽牌 / 抽签 / 择日工具 |
| 要不要生辰 | 要档案 / 开箱即用 |
| 上手难度 | L1 秒懂 → L4 深度（列表排序依据） |
| 等多久 | 即时 / 需等待（八法异步） |
| 花钱方式 | 全免费 / 免费盘面+付费深挖 |
| 文化源流（内部，不对用户显示宗教字样） | 如七政四余=中华+源流印度；观音灵签=中华+源流民间信仰 |

**难度 4 级口径（建议）**：L1 开箱即用秒出（灵签/塔罗单张）；L2 轻交互即时（六爻/梅花/塔罗多阵）；L3 要生辰档案（占星/八字单法）；L4 多法综合异步等待（八法合一）。

**新手分流 5 问题（第一版措辞，待调）**：
① 看看我这一生的命 ② 心里有件事想问问 ③ 挑个日子/取个名字 ④ 抽张牌随便玩玩 ⑤ 测测我是什么性格

**方法卡内容**：名字 + 一句白话（回答什么问题）+ 标签 chips（开箱即用/要生辰/免费起）+ 预计耗时；列表按 L1→L4 排。

**开关位置**：功能设置页加项（现有 7 项设置框架）+ 首页右上角轻量切换；默认开。

**八法合一的新定位**：卡片墙中一张「套餐卡」（L4），与单法并列，不再当首页主角——待用户确认能否接受。

### Greenfield 讨论：抛开现有资源的最合理方案（2026-09-12）

**核心论点：最合理的不是更好的分类，而是让普通用户不必面对分类——意图在台前，方法在幕后。**

理想信息架构：
1. **首页主视觉 = 意图入口**：「你想问什么？」自由输入（未来接王先生 agent 识别）+ 4-5 个快捷意图（问件事/看自己/择吉取名/随手测/测性格）
2. **意图后是「推荐带理由」页**：如「看事件走向→六爻；看心理动机→塔罗；要干脆指引→灵签」，并永久保留「我自己挑方式」逃生舱。推荐逻辑冷启动用人工配置表（意图×情境→方法），后端 routing/router.py 的领域路由是雏形
3. **文化从导航骨架降级为视觉皮肤 + 筛选项**，退居「探索全部」工具浏览器；中华/西方的氛围美学保留
4. **心理测试并入「看自己」意图**，不再与占卜平级（八字/占星/MBTI 在同一意图下是"三种认识自己的视角"）
5. **Agent 站门口不进庙里**：只做导诊，摇卦/洗牌/翻牌/看盘等仪式完整保留在各工具内
6. **个性化回访区**：本月流运、我的命盘一键回看
7. **未登录态**：L1 工具即玩转化（灵签/单张塔罗），注册建档后解锁生辰类

理想方案代价：推荐错误的逃生舱必须在；品牌偏好用户需老手模式直达；等于重做首页、两个 HUB 合并为一个工具浏览器。

**三档光谱**：
- 保守 = 丁方案原样（固定问题 + 改造现有两 HUB）
- **折中（Agent 推荐落点）** = 意图卡首页（预留自由输入升级位）+ 两 HUB 合并为「探索全部」标签浏览器 + 推荐带理由/可自挑
- 激进 = 纯对话式首页（依赖意图识别准确率，暂不建议）

## 一、需求原话与核心目标

用户觉得「工具相对全，但新手引导不够、分类模糊」。方向上提出两条候选分类轴：
- **方向甲：按地域/文明**（中国 / 欧洲 / 印度 / 泰国……）
- **方向乙：按流派/宗教**（道教 / 佛教 / 纯粹占星 / 独立流派如塔罗、雷诺曼各自一派）

**两个硬目标（无论选哪条轴）**：
1. **快**：新用户第一次到首页，就知道沿哪条渠道走，能快速找到他心目中本来就想找的占卜方式
2. **可扩展**：分类法要能容纳未来更多占卜方式进入，不用每次重构

**范围约定**：心理测试（MBTI/未来 OCEAN）不参与占卜分类，保持独立第三区。

## 四、第三类候选思路（供决策参考，不替用户拍板）

### 方向丙：按「用户想干什么」（使用形式/目标）分
现状国学 HUB 的 4 张场景大卡（命盘/问事/择吉/流年）其实已是这个思路，可顺势全站统一：

| 分区（白话题） | 装什么 | 现有功能 |
|---|---|---|
| 看我这一生（出生时间排盘） | 命理推命类 | 八法合一各盘、西洋占星本命盘 |
| 当下问件事（即时起卦抽牌） | 随机取数类 | 六爻/梅花/六壬/奇门时家/灵签/塔罗/雷诺曼 |
| 挑日子取好名（择吉工具） | 实用工具类 | 黄历、起名、配对 |
| 看今年运势（周期运势） | 流运类 | 生肖流年、塔罗年运牌阵等 |

- 优点：**新人心智成本最低**（不用先懂「国学/术数/流派」概念）；同一交互体验的功能聚在一起；与现有 4 大卡结构连续
- 缺点：地域/流派特色被淡化（用户明确想要的「中国/欧洲」文化归属感给不了）；同一法跨形态时（奇门既排终身盘又能时家问事）会重复挂

### 方向丁：混合轴（主分类 + 标签）
- 主分类只保留用户一眼能懂的大区（如：中国术数 / 西方卡占星占 / 心理测试）
- 每个功能打**多维标签**（地域、流派、形式、是否需生辰、是否付费深度解读），支持按标签筛选/搜索
- 优点：扩展性最强，模糊案例靠标签不强制二选一；缺点：实现成本最高，需要先建功能元数据表

## 五、必须摆上桌的代价：宗教分类的合规风险

方向乙若用「道教/佛教」作为**面向用户的分区名**：中国大陆应用商店对「宗教活动 + 算命占卜」组合审核敏感，按宗教给占卜功能归类，比现在的「国学/西式」中性包装更容易被认定为传播封建迷信/宗教活动。
- 默认建议：即便选乙方向，分区名用**文化/术数流派**口径（如「中华术数」），不直接用宗教名；「佛教」类功能用「民间灵签」之类的俗名
- 这是用户看不见的审核代价，先记录，实施前需用户知情拍板

## 七、新手引导的独立议题（与分类正交，需单独定）

分类解决「东西放哪」，引导解决「新人怎么上手」，是两件事。候选手段（未细查，立项后另调研）：
1. 首页改**提问式入口**：「想算什么？」→ 选项白话（问姻缘/问事业/就想抽个签/看看我的命盘…）→ 自动路由到具体法
2. 首次登录 onboarding 小问卷：生辰有没有 → 想玩中国的还是西方的 → 推荐 2-3 个入口
3. 黑话翻译：「九法合一」「断前尘」等内部术语在面向新用户处加白话副标（节139 改八法时可顺带）
4. 每个 HUB 卡补一句「适合什么人、回答什么问题」

注意：现有路由层（`routing/router.py`）已有「主问领域 → 主/辅法」的零 LLM 查表机制，提问式引导可复用其后端能力，主要是前端工作。

## 八、待用户拍板/思考的问题

1. **先选大方向**：甲（地域）/ 乙（流派）/ 丙（用户目标）/ 丁（标签混合）——或甲乙丙的某种组合（如主用丙、大区保留文化色彩）
2. 文化归属感 vs 上手零门槛，哪个权重更高？（这决定甲/乙 vs 丙的取舍）
3. 印度、泰国分区是「现在就开空区占位」还是「等真有功能再开」？（空区对新人是噪声）
4. 七政四余、观音灵签这两个混血儿按什么口径归？（按现行文化 = 中国；按起源 = 印度）
5. 分类重构与节139（八法）、节130（九法单飞）有先后依赖：是否等八法落地后再做？
6. 新手引导四种手段想做哪几种？是否做首次 onboarding 问卷？
7. 是否接受为丁方案建一张「功能元数据表」（每法：地域/流派/形式/需生辰/付费形态）的小基建成本？
