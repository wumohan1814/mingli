# 一、为什么（背景，必读）

- 命理太初是一个 **AI 命理 H5 应用**，面向**不懂命理术语的普通用户**，用**大白话**做多流派解读。
- 命理太初过去通过一个第三方开源项目 **`Brhiza/mingyu`（命语）** 的软件包拿到了一批能力（排盘、占卜）**和一批中文文案**。
- 现在用户已决定：**全部自研，不再用 `mingyu` 的任何东西**（含文案）。
- ⚠️ **合规原因**：`mingyu` 的**根仓库是 `AGPL-3.0-only`**。命理太初是**面向公众的网络服务（SaaS）**，正落在 **AGPL 第 13 条**（把修改版作为网络服务提供给用户时须提供对应源码）的射程内。**把它的文本搬进命理太初 = 授权传染。**
- ✅ **同时，命理术数（八字 / 紫微 / 奇门 / 六爻…）本身是公有领域的传统文化**：作者不可考，规则属"方法/思想"，**不受版权保护** → **我们完全可以自己写**。
- ✅ **用户已决定：古籍原文也不沿用**，**一律从公网重新采集** —— 理由是**"来源链干净"**（将来无需解释"这份文本从哪来"）。

# 二、🚨 三条最高纪律（**违反即任务作废**）

### 纪律 1：**不碰 `mingyu` 的任何文本**
- 🚫 **不要** clone / 下载 / 打开 `Brhiza/mingyu` 仓库，**不要**读它的提示词、话术、术语解释、规则表、古籍文件

- 理由有二：① 避免把 AGPL 文本带进项目 ② **避免"看过之后写"带来的"衍生 vs 独立创作"举证麻烦**

### 纪律 2：**按主题从零生成，不"照着描述改写"**
- 清单里给的是**"要生成什么"（主题 + 用途 + 体量）**，**不是原文** → ✅ **这是故意的**
- 🚫 **不得**去找任何"参考文本"来改写（包括其他网上的同类产品文案、其他开源项目的提示词）
- ✅ **生成的依据只能是两样**：① **术数规则本身**（公有领域）② **公网古籍原文**（自行采集）
- ⭐ **判断标准（自检用）**：如果你能指出"这句话是从某处改写的"，那就**不算独立生成**，要重写。
- ⚠️ **特别容易踩的地方**：字数限制的"结构模板"（如"先讲盘面事实、再讲倾向、最后给建议"）属于**方法**，可以用；但**具体的句子**必须自己写。

### 纪律 3：**古籍从公网重新采，并记录来源**
- ✅ 古籍**要**采（它是生成依据），但**来源必须是公网可查的公有领域版本**
- ✅ **每一条古籍内容都要记：书名 / 篇名 / 来源 URL / 采集日期**
- ⚠️ **区分两样东西**（这是最容易出错的地方）：
  | 类型 | 性质 | 处置 |
  |---|---|---|
  | **古籍原文**（文言） | **公有领域** | ✅ 可采集使用（记来源） |
  | **现代人的白话转写 / 注释 / 整理** | **现代创作，受保护** | 🚫 **不要采** —— 白话部分**自己写** |

# 五、内容规范（**硬性**）

## 5.1 语气与读者
- **读者 = 不懂命理术语的普通用户**
- **大白话优先**：术语第一次出现要有一句人话解释（复用 §4.1① 的术语总表）
- **不用恐吓性表述**（"大凶""必破财""克夫"这类）→ 用**倾向性、可行动**的说法

## 5.2 🚨 不做数字吉凶评分（**这条是产品红线**）
- 命理太初已定：**输出「吉 / 凶 / 平 + 置信度 + 分歧标注」，不输出吉凶总分、百分比、数字评分、匹配度**
- 🚫 **不要**写"72 分""成功率 80%""契合度 9.5"
- ✅ 分歧要**并列保留**，不要抹平成一个结论
- ⚠️ 同理：**不要给"你比 X% 的人更…"这类人群比较**（本项目没有可用常模）

## 5.3 免责口径
- **复用命理太初既有免责体系的口径**（读 `frontend/public/data/ui-copy.js` 里现有的 `disclaimer` 文本作为风格参照）
- **不要新造概念**；若某类内容需要新免责，**列出来交用户裁决**，不要自己发明

## 5.4 不越界（**合规红线**）
🚫 **不要生成**以下类型内容：
- **医疗 / 诊断 / 用药建议**（涉及"健康"时只讲"留意作息"，不讲病症）
- **投资 / 交易建议**（尤其**不做**币圈、合约、个股预测）
- **婚恋断言**（不要写"你们不适合在一起""必离婚"）
- **法律 / 司法判断**
- **对具体真人（名人）的事实性断言**（尤其**不要编造净资产/市值/荣誉**）

## 5.5 事实性要求
- 凡是引用古籍，**出处必须真实可查** → 记书名 + 篇名 + URL + 采集日期
- 🚫 **不要编造古籍原文**（万一某句找不到，写"未找到"，不要凑）

# 六、交付物与格式

## 6.1 落盘位置
`40_节/待办/节128-附件/文案交付/`（新建目录）
- 按批分子目录：`A-提示词/`、`B-证据层/`、`C-术语与数据表/`、`D-文档与界面/`
- 加上 §4.1 的《文案规格确认》与《术语总表》

## 6.2 格式（**必须可被项目直接解析**）
**每条文案一个 JSON**，命名 `{批次}-{模块}-{用途}.json`：

```json
{
  "id": "A-bazi-pattern-prompt",
  "batch": "A",
  "category": "prompt",
  "title": "八字格局解读提示词",
  "target_path": "backend/prompts/interpret/bazi-pattern.md",
  "content_zh": "（正文；**必须是你自己写的**）",
  "constraints": {
    "word_count": 1200,
    "structure": ["盘面事实", "倾向判断", "分歧标注", "行动建议"]
  },
  "basis": {
    "type": "术数规则 + 古籍",
    "classics": [
      {"book": "滴天髓", "chapter": "…", "url": "…", "collected_at": "2026-09-11"}
    ]
  },
  "meta": {
    "generated_by": "文案 Agent（写出模型与日期）",
    "version": 1,
    "self_check": "无照抄；术语已对齐术语总表；无数字评分；无越界内容"
  }
}
```

## 6.3 古籍采用**单独格式**（便于与生成内容区分）
```json
{
  "id": "C-classic-ditiansui",
  "batch": "C",
  "category": "classic_source",
  "book": "滴天髓",
  "chapter": "…",
  "source_url": "…",
  "collected_at": "2026-09-11",
  "is_classic_original": true,
  "content_zh": "（古籍原文，文言）"
}
```
⚠️ `is_classic_original` 必须为 `true` 才算"可保留"；**任何现代白话转写都不得标 `true`**。
