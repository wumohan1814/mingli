## 〇、铁纪律（违反即返工）

1. **只允许在 `backend/paipan-node/paipan-core/` 内新建/修改这些文件**：`src/rules/<cap>.js`、`src/capabilities/<cap>/index.js`、`tools/fixtures/<cap>.json`（+ 自己产出的 `<cap>-golden.json`）、`tests/<cap>.test.mjs`、临时探针（放 `tools/_probe/`，完成后可留可删）。
   **不许碰**：`tools/compare/run-compare.mjs`（登记表已预接线）、`README.md`、`server.mjs`、`package.json`、vendor、前端、`40_节/`、`00_根/`、`99_状态/`；**不 git commit**；**不删除任何既有文件**。
2. **旧实现只许黑盒运行，不许读其源码**（vendor 目录）。探针脚本只 import 并调用、打印输出。
3. **文案纪律（母节 §3.6 铁则）**：🚫 不从 vendor/mingyu 复制任何文本（连"照着改写"也不许）。排盘字段之外的**现代白话文案**按主题从零生成；**古籍原文/传统口诀**（周易卦辞爻辞、纳甲口诀、观音签诗、协纪辨方书宜忌、太岁星君名等）**从公网重新采**（web_fetch 可用），在 rules 文件里**记来源 URL**。卡牌名/卦名/星名等**盘面标识**属事实，与旧实现一致（公有领域传统内容）。
4. **中文/UTF-8 文件一律用 write/edit 工具写，禁止 shell 整文件覆写**（pwsh 中文编码不可靠）。
5. **确定性零 LLM**：内核不触网（运行时不 fetch）、不读时钟参与结果、不 import llm/net/io；缺输入抛错，不回落"当前时间"。唯一例外 `meta.calculatedAt`（信息性）。
6. **关键字段分类规则**：`defaultKeyFields` 只放**排盘计算字段**（数值/干支/卦象符号/宫位/索引/关系/牌 id 等确定性盘面事实）；**白话文案、释义段落、歌诀**放信息性（新实现用干净来源，允许与旧实现不同并逐条列出）。盘面标识类（卦名/牌名/星名/宫名/掌诀名）**进关键字段**（公有领域传统内容，必须一致）。
7. **fixtures 代表性**（README §3.3）：跨年代/边界（早晚子时、节气、闰月、月末年末、跨年）必须覆盖；夹具 `input` 用统一形态（见各能力契约），旧实现不认的形态由登记表的 `toLegacyInput` 转换（已接线，勿改）。
8. **对拍门禁**：`node paipan-core/tools/compare/run-compare.mjs --capability <cap> --verbose` 必须 **PASSED（关键字段 100%）**；然后 `--save-golden` 落 `<cap>-golden.json` 并 `--use-golden` 复跑 PASSED。达不到 100% 时诚实报告差异清单与你的判断，不许伪造、不许改 keyFields 放水。
9. **多子代理并行**：本会话可能同时有 3 个内核子代理在 paipan-core 不同能力目录下工作。你的文件与别人不重叠；**编辑前先读**（文件若"since read"变化即重读）；不要碰别人目录里的文件。

## 一、通用管线形态（照 xiaoliuren 样板）

`src/capabilities/<cap>/index.js`：四段纯函数（① normalizeInput ② 历法/起局 ③ 格局判定 ④ assemble），导出 `generateXxxCore(...)` 与旧实现**同签名同形状**（stripInternal 之后的生产契约形状）；`src/rules/<cap>.js`：单一权威规则源（Object.freeze + 来源标注）；`tests/<cap>.test.mjs`：node:test 确定性用例（含已知样例写死断言、纯函数性、边界）。

## 二、各能力契约（来自 server.mjs 实测调用方式；输出形状需你黑盒探针确认）

### 节155 六爻 liuyao / 梅花 meihua
- 旧实现：`generateLiuyao(customDate: Date|undefined, options: object)`（options 可带手工爻值/铜钱记录）；`generateMeihua(customDate, settings: object)`（settings 即报数等起卦设置）。
- 夹具 input 形态：`{customDate: "ISO+08:00", options?: {...}}` / `{customDate, settings?: {...}}`。
- 排盘字段：起卦（卦名/上下卦/动爻/变卦/本卦）、六爻装卦（纳甲干支/六亲/六神/世应/伏神）、梅花体用（体卦用卦/互卦/变卦/生克五行格局）。
- 文案字段：卦辞爻辞（周易原文，公网采源）、断语白话（按主题从零生成）。
- 风险：纳甲/世应口诀流派差异——以旧实现口径为准（黑盒探针定位）；早晚子时排日分歧先锁旧口径。

### 节156 灵签 ssgw / 黄历 almanac / 生肖 zodiac
- **ssgw**：旧实现 `drawRandomSign(options)`，options 可带 `seed`/`replay`（确定性重放）。夹具 input：`{options: {seed: 123, replay: true}}` 等。若响应含签诗正文 → 签诗为观音灵签（传统 100 签，公网采源，签号体系必须与旧实现同一编号——老记录不串号）；若只含签号 → 内核只做抽取。**随机源必须与旧实现同 seed 同结果**（探针反推 PRNG 算法，常见 seedrandom/mulberry32 逐一试）。
- **almanac**：旧实现 `generateAlmanacSelection(params)`，params = {topic, startDate, endDate, participants?}（server.mjs 校验后透传）。夹具 input：`{params: {...}}`。排盘字段：逐日 宜忌/冲煞/建除十二值/二十八宿/九星/彭祖百忌/方位神/逐时时课 的**结构化数据**（日期、干支、值符名等）；文案字段：宜忌白话条目。⚠️ **生产契约**：server.mjs 的 computeDivination 会读 `raw.evidenceAnalysis` 投影出 `candidateGroups`（preferredDates/conditionalDates/cautionDates/statusByDate/hardConstraints/realityConstraints）——你的内核输出**必须自带同结构 evidenceAnalysis**（由你自己的规则生成，这是自研"证据层"），否则前端候选分组为空。对拍不比对 evidenceAnalysis（被 strip），但你要自测该结构存在且形状正确。
- **zodiac**：旧实现 `calculateZodiacYearFortune({zodiac, year})`；server.mjs 还另调 `getYearTaiSui(yearGanZhi)`（60 甲子→值年太岁星君）。你的内核模块应导出**两个函数**：`calculateZodiacYearFortuneCore` 与 `getYearTaiSuiCore`（太岁星君名从公网采源，传统 60 太岁神名）。夹具 input：`{zodiac: "鼠", year: 2026}`。排盘字段：流年干支/太岁支/六合三合关系/冲刑害破/五行关系/贵人落宫等**结构化字段**；文案字段：流年白话、贵人叙述、行动信号文本（按主题从零生成，允许与旧实现不同）。

### 节157 塔罗 tarot / 雷诺曼 lenormand
- 旧实现：`drawTarotSpread(spreadType: string, options: object)`；`drawLenormandSpread(spreadType, options)`。options 可带 seed/replay/interactiveSamples/question。
- 夹具 input：`{spreadType: "single"|"three"|"love"|"career"|"decision"|"fourSeasons"|"celtic"|..., options: {seed: 123, replay: true}}`。
- 排盘字段：牌 id、正逆位、牌位名/序号、牌序。**同 seed 必须与旧实现完全一致**（反推其 PRNG）。
- 牌阵定义：节157 把 `mingli-tarot-spreads.mjs`（自研覆盖层）升级为**唯一牌阵来源**——内核里建自研牌阵表（78 塔罗单/三/爱情/事业/抉择/四季节/凯尔特十字/马蹄/六芒星/年运/十二宫 + 36 雷诺曼 7 阵），**牌位名与旧实现一致**（前端展示不退化）。
- 牌义正文：已在前端 CONTENT（节135），内核不复制正文；牌名/牌 id 与现有体系一致（读 `frontend/public/data/content/tarot-zh.js` 与 lenormand 对应文件确认 id/name 映射，作为参考，不搬正文）。
- 随机源反推是本节核心难点：探针打点（同 seed 序列），对比常见 PRNG 的序列特征。
