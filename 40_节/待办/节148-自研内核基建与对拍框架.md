## 目标

为 17 个能力的逐个自研替换搭好地基，使后续每个子节只关注算法本身；并锁定一项不可逆的架构决策：**自研内核用什么语言写**。

## 一、头号决策：内核语言（✅ 2026-09-13 用户已拍板：B = JS/TS）

**裁决：自研内核用 JavaScript/TypeScript 编写**，与 paipan-node / iztro 同生态，可在 WebView 同进程运行，为节142 胖 APK 省掉一个移动 Python 运行时。

落地含义（本节执行时遵守）：
- 内核目录建在 Node/前端侧（具体路径开工时定，候选 `paipan-core/`），Python 后端经现有子进程/HTTP 契约调用，**接口 JSON 形态不变 → 前端与编排层零改动**
- 紫微 iztro（JS）同生态直接复用；八字 lunar-python（Python）的上层逻辑在 JS 侧重写或寻找 MIT 的 JS 历法库（节150 收口时核实，历法轮子不重造原则不变）
- 对拍框架用 JS/TS 写；类型与 lint 配置在基建节一并建立
- 与 Python 侧的长期 IPC 保留到内核全部迁移完后再评估是否去除

| 方案 | 优点 | 代价 |
|---|---|---|
| A. Python（进 FastAPI） | — | 未选：胖 APK 需带 Python 运行时 |
| **B. JS/TS ✅ 选定** | 与 iztro 同生态；胖 APK 可进 WebView 同进程；排盘本就跑在 Node | Python 后端继续经子进程/HTTP 调用；对拍工具链新建 |
| C. 混合 | — | 未选：双运行时长期并存 |

## 二、交付物

1. **内核目录骨架**（语言定案后建）：`paipan-core/`（或 `app/paipan_core/`），按能力分子模块；统一输入/输出契约（对齐现有 Node HTTP 接口的 JSON 形态，保证前端零改动）
2. **纯函数管线规范**：输入归一化 → 历法/起局（纯函数）→ 格局判定（纯函数）→ 输出装配；构卦/动爻/互变卦等推导禁止与 IO/LLM/格式化耦合（教训：耦合函数会放大索引小错为全链路错配）
3. **单一权威规则源**：每个能力的规则表/术语表/数据表只允许一份，调用方只读不抄
4. **对拍框架**（核心）：
   - fixtures 批量喂给「旧实现（vendor/npm）」与「新实现」，输出归一化后字段级 diff
   - 浮点字段阈值可配；无序集合排序后比；生成对拍报告（一致率/差异样例）
   - 门禁：关键字段一致率 100% 才允许在对应子节下线旧实现
   - fixtures 由旧实现产出但需人工抽查代表性（生辰跨年代/节气边界/早晚子时/夏令时等）
5. **依赖锁定**：`mingyu-core` 写死精确版本（现状 package.json 是 `^0.2.1` 而奇门终身局用 vendor 0.2.2 构建产物，口径需在本节对齐核实），对拍期间禁止升级
6. **依赖扫描脚本**：一条命令列出 server.mjs / 内核中所有 mingyu 引用，供逐节勾销
7. 零 LLM 校验：内核测试全确定性，不触网

## 三、验收

- 一个示例能力（挑最简的，如小六壬或生肖太岁）走通「新实现 → 对拍 100% → 开关切换」全流程作为样板（该能力的正式替换仍归对应子节，本节只证明管线可用）
- `node --check` / 后端 `node --check server.mjs` 与 Python 语法检查全绿
- 后续子节可直接复用对拍框架，不需要再造
