## 用户原话
"立A和B"（B = 确定性预判标记层；由 `reference-not in project/` 参考项目调研产出）

## 我的复述
在**排盘之后、LLM 解读之前**，用**纯代码**算出一组命理标记（如月令十神 / 根气摘要 / 寒燥标记 / 七杀标记 / 墓库标记），作为"确定性基础层"喂给各方法模块 —— 把"该看什么"**从 LLM 挪到代码**，从而降低幻觉面与 token 消耗。

## 期望形态（验收标准 · 用户可观察）
- 方法模块的输入里出现**确定性标记**（如"月令：申金（得令）｜根气：有 / 无｜寒燥：偏寒"）
- 同类命盘的解读**更聚焦**（不再由模型自行"猜该看哪里"）
- 解读质量不降、幻觉类错误减少（以断前尘命中率 / 校准反馈量前后对比为凭）
- **不新增 LLM 调用**、排盘契约字段不变

## 覆盖声明（v0.21）
- 本节点证明：太初现有确定性层**确实没有**这一块（见 §现状坐标，三个模块职责已逐一核对）
- 本节点未证明：标记口径的设计（需按 9 法逐法确认）与**实际收益数字**（须落地后取数）

## 现状坐标（Agent 用 · 已核实）
太初现有"确定性层"共三块，**都不是"预判标记"**：
| 模块 | 职责 | 是否含命理标记 |
|---|---|---|
| `backend/app/paipan/engine.py` | 排盘事实（lunar-python + Node 引擎） | ❌ 只出盘面事实 |
| `backend/app/paipan/slicer.py` | **字段裁剪**（其头部注释明说目的是"压上下文"） | ❌ 裁剪，不判断 |
| `backend/app/paipan/scorer.py` | 契合度/校准打分：`collect_feedback` / `severity_counts` / `hit_rate` / `quality_score` / `chain_completeness` / `calibration_weight` | ❌ **无命理标记** |

→ 结论：**"排盘后、解读前该看什么"目前完全交给 LLM 自己判断**，这是幻觉面的结构性来源之一。

## 复用判断

## 设计取向（v0.17 乐高原则 · 大改必过，结论写回本节）
- **轻量**：标记计算是纯 CPU 的确定性代码，不引入模型、不新增进程
- **接缝**：标记规则按**法**隔离（9 法各自的标记表独立），新增方法只需登记自己的标记，不改公共流程
- **埋点** ⭐：标记结果建议落库或落日志（否则无法复盘"标记是否真的降低了幻觉"）
- **开关**：整层做成**可关闭**（按项目/方法灰度），便于对照效果

## 方案选项
- **A（推荐）**：**先做八字（4 法）** —— 参考项目给的正是八字口径，可直接对照落地；验证收益后再按紫微/西占/七政/奇门/五运六气逐法扩
  - 代价：覆盖只到 4 法；效果：最快拿到"降幻觉"的可测收益 + 建立标记表范式
- **B**：9 法一次性全做
  - 代价：口径要逐法新设计（中-大工作量，且 6 个法没有现成参考）；效果：一步到位
- 用户选择：**B（九法全做）**—— 2026-09-11 用户拍板"倾向于 B、一口气全做"；已落地八字4法，其余5法待做（建议挂节128 之后）

## 禁碰清单

## 冲突检查
- 与 **ADR-0001**（排盘层自研 + 复用边界）**一致**：本层是"胶水/切片/打分/提示词全部自研"的延伸
- 与 **ADR-0002**（校验仅断前尘阶段）**不冲突**（标记发生在解读前，属确定性计算，不走校验子会话）
- 与 `docs/架构设计.md` §5.3（契合度打分纯代码防幻觉）**同向**，不冲突

## 结构反思（破竹 §8）
- 哪里难：太初的确定性层三块职责**各自独立但缺"面向解读的语义层"**（排盘给事实、slicer 压上下文、scorer 事后打分），中间"该看什么"这一环没有归属
- 结构上怎么改：新增"标记"环节挂在 `paipan/` 下（或独立小模块），输出直接进方法模块输入
- 下次会怎样：新增方法只需登记标记表；"该看什么"不必再靠提示词反复叮嘱

## 控制点结果
- 回归：`py_compile` 通过 + import 冒烟通过（2026-09-12 实测）；**完整回归（9 法排盘与解读主链路 + 断前尘 + 报告 8 板块）待 docker 环境**
- 安全 / 数据：不适用（纯计算层，无数据边界改动）；但**标记入 prompt 后须复核不夹带敏感/超长内容**
- 性能：**必须给数字**（标记计算耗时 + token 变化；2 核 894MB 环境下不得显著加重主链路；确定性计算优先，禁止为此新增 LLM 调用）
