## 结构反思（破竹 v0.8 触发：定位 ≥3 次 grep + 同区域第 2 次修改）
- 哪里难：SPA 视图切换后滚动位置错乱问题反复出现（REQ-099 建档页一次 + 本次校准/结果页一次），且定位需多次 grep 散落的 scroll 调用
- 结构上怎么改：滚动复位统一收敛到导航中枢 `navigate()`（已实施），不再靠各页面各自补 useEffect 回顶
- 下次会怎样：同类"切页位置错乱"问题一处根治，无需逐页排查

### 第③组 西式域反思（同区域第 2 次修改：初版 → 验收打回 → 二版通过）
- 哪里难：①返回入口初版自创了虚线小链接「← 返回西式占卜」，与全站既有的底栏大按钮模式（`back-row fill` + `btn-outline`，星座/国学各页同款）不一致，被用户打回；②H5 横滑交互在桌面网页端无法用鼠标验证，用户验不了滑动特性；③三卡牌堆初版错开方向（左/右）与用户预期相反。
- 结构上怎么改：
  1. **新入口先对齐既有控件**：加「返回/首页」类入口时，先 grep 同类页面（如星座页底部 `UI_COPY.buttons.back_options/back_home`）照抄结构与文案，不自创控件样式与位置；
  2. **横滑容器标配 wheel 转横向**：凡 `overflow-x:auto` 的触摸横滑区，同步挂非 passive wheel 监听把 deltaY/deltaX 写入 scrollLeft（到端放行竖滚），桌面端即可滚轮验收；
  3. **摆位数学单一权威**：抽牌槽位直接复用读牌板阵型坐标与摆位公式（TarotReadBoard），抽牌/读牌两块板同源，杜绝两套坐标漂移——此决策一次做对，未返工。
- 下次会怎样：西式/国学各页新增导航入口有现成模式可依；新做横滑组件默认带桌面滚轮通道；凡「演出态→结果态」同屏切换，坐标数据一律复用结果态那份。

### 第⑤组 档案层反思（删档案外键遗漏 + 默认档补位缺失）
- **哪里难**：①删除档案的子表清理清单容易漏（本次漏了 `agent_messages`），数据库外键开启时报错要靠用户真机触发才能发现，静态 grep 难全量覆盖；②删除默认档案后默认位悬空，属于"正常路径之外的边界态"，初版实现容易遗漏。
- **结构上怎么改**：
  1. **删除操作加回归防护**：每次新增带 `case_id` 外键的表，必须同步在 `delete_case` 的子表清理清单里追加（类似迁移的约定），可以在代码审查 checklist 里加一条"新增外键表 → 检查 delete_case 清理清单"；
  2. **"默认值"类状态要有兜底转移逻辑**：凡有"默认选中/默认使用"概念的列表（默认档案、默认模板等），删除默认项时必须自动转移到下一项，不能留悬空状态——这是边界态而不是异常态，应在初版就写。
- **下次会怎样**：再做带"默认项"的列表模块，删除逻辑第一版就把默认项补位写进去；新增外键表时 checklist 自动提醒补 delete 清理清单。

### 第⑦组后台反思（5 项修复集中爆发：接口有 UI 漏 + 中文名映射不全 + 资产预置缺失）
- **哪里难**：① 后端已有接口但前端 UI 漏做按钮（重置密码、重置档案），静态 grep 不容易发现"接口有但按钮没挂"的缺口；② 提示词分类从 15 个扩到 33 个后，前端中文名映射和描述文案没同步更新，后台裸显示英文名；③ 前端硬编码的静态资源（塔罗/雷诺曼卡面图）与后台 `asset_slots` 表是两套体系，项目初期先硬编码上线、后台资产热更功能后做，导致后台看到大量"未配置"但前台实际已有图。
- **结构上怎么改**：
  1. **后台操作按钮与后端接口做一个对账清单**：每新增一个 ops 接口，同步在前端用户管理/档案列表对应位置挂按钮，接口列表和 UI 按钮列表是同一份清单的两面，不能各自演化；
  2. **枚举映射表放后端权威、前端从接口拉**：提示词中文名、资产 key→中文名这类常变映射，不应两端各写一份，应由后端列表接口返回中文 label，前端直接用，避免前端版本滞后；
  3. **资产热更的预置初始化要跟静态资源同步**：前端有图 → 后台 `asset_slots` 就该有初始行（可以写一个 init 脚本/迁移，首次启动时从现有静态资源扫描入库），不能出现"前台有图后台显示未配置"的认知错位。
- **下次会怎样**：新增后台接口时顺手挂 UI 按钮；新增提示词/资产分类时后端返回中文名、前端不复维护；项目上线前跑一遍"前台所有静态图 → 后台资产槽位"对账。
