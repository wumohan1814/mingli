## 4. 已知问题（接手时须知，勿重复上报）

### 4.1 `test_paipan.py::test_fixture_snapshot_anchor` 失败（既有，无害）
- **现象**：chart.json 快照与当前排盘引擎输出在 `<root>.western.summary.patterns[0]` 不一致（西方盘 pattern 文案英文/中文差异）。
- **性质**：夹具漂移，非引擎 bug（排盘结果本身正确）。
- **建议**：确认当前输出正确后，重新生成 `backend/tests/fixtures/chart.json`（用 `paipan(**STANDARD_KW)` 输出覆盖快照），或标注为「已知夹具漂移、暂跳过」。

### 4.2 `*_node_endpoint_*` 本机偶发失败（环境性）
- **现象**：本机 Python httpx/urllib 请求 node **v24** 的 `server.mjs` 时 `RemoteProtocolError`/`WinError 10054`（连接重置）；node fetch / curl / 最小 node server + Python 均正常。
- **性质**：本机 node v24 + Windows 的特定交互问题；**生产镜像 node 是 v22.14.0，无此问题**。
- **处理**：本机跑失败时，可用 node v22 复验，或标记为环境性跳过；不要把这类失败当 Bug 上报。

### 4.3 测试纪律
- LLM 一律 mock（`chat` 打桩），**不真调 DeepSeek**（省 token + 稳定）。
- Node 端点测试真实拉起 `server.mjs`（随机端口），node 不可用则 skip。
- 数据库用临时库隔离（conftest 的 fixtures），不污染本地 `backend/data/*.db`。

## 6. 工作流程

1. **接手**：读本文件 + `docs/需求表.md` + `docs/Bug管理表.md`，了解现状与待办。
2. **跑基线**：`cd backend && python -m pytest tests/ -q`，记录结果（当前基线：98 passed / 1 既有夹具失败）。
3. **发现 Bug**：登记 `docs/Bug管理表.md`（BUG-xxx，含严重度 S0–S3、复现步骤、期望）。
4. **验证修复**：修复后跑相关测试 + 真机复验，更新 Bug 状态 🟡→🔵→🟢。
5. **验收需求**：新 REQ 上线后逐条验收，更新 `docs/需求表.md` 状态。
6. **收尾**：把本 Session 的测试结论、新 Bug、状态变更同步回需求表/Bug 表。

---

## 7. 与需求表 / Bug 表的联动

- **需求（REQ）**：功能上线前，测试组按需求验收标准验证；通过后 REQ 状态 🟡→🟢。
- **Bug（BUG）**：测试发现的缺陷登记 Bug 表；Bug 修复涉及新功能时在需求表补 REQ；Bug 关闭时注明复现/修复 commit。
- 两份表都在 `docs/` 下，均有使用说明（字段、状态机、严重度/优先级）。
