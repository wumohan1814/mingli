node --version        # 需 22+（仅排盘引擎子进程用）

# 2. 安装后端依赖（首次）
cd C:\Users\wumoh\Documents\Vibecoding\taichu
pip install -e backend            # 运行依赖
pip install -e "backend[dev]"     # 含 pytest（做测试才需要）

**注意**：
- **前端不需要 npm install**（走免构建 CDN React，依赖已本地化到 `frontend/public/vendor/`）。
- **Node 排盘依赖不需要 npm install**（已在 `backend/paipan-node/node_modules` 和 `vendor/`）。
- 不要 `pip install lunar-python`（已装）。

**通过标准**：`python --version`、`node --version` 正常；`pip install -e backend` 无报错。

## 阶段 3 · 前端浏览器实测（核心，必做）

**做什么**：前端 JSX 之前只靠人工审读 + 括号平衡核对，**没做过机器转译**（`@babel/core` 依赖不全）。必须在浏览器实测 8 页全流程。

**怎么做**（按顺序点一遍，每一步看结果）：
1. **落地页**：打开 http://localhost:8000 → 见「太初 · 事业运势趋势参考」+ 三卡（多流派综合/可修正/随时问）+ 底部免责声明。
2. **注册/登录**：点「开始」→ 注册一个新账号（用户名≥3 位、密码≥6 位）→ 应跳到建档页。
3. **建档**：填出生年/月/日/时辰/性别/出生地，**经度纬度可选**（选「北京」会自动填坐标）→ 提交。
4. **等待/断前尘**：应看到「正在综合九流派推演」+ 进度条逐格点亮 → 自动跳到「问卷校准」。
5. **问卷校准**：逐条点「确认/否认/修正」；**修正**会弹输入框收 `user_note` → 全部完成后提交 → 应短暂显示「校准完成 · 契合度 X%」再跳预测。
6. **解读/预测**：轮询 job → 显示「综合解读」+ 趋势卡 + 各领域结论 + 置信度 + 底部免责。
7. **追问修正**：输入问题发送 → 应得到带免责的回复；可返回解读。
8. **档案**：点「我的档案」→ 应显示建档信息 + **盘面摘要（日主/农历）** + **校准记录** + **对话历史** + 经纬度降级提示（若未填经纬度）。
9. **皮肤**：底部皮肤切换器，MVP 只有「国学」可用，占星/塔罗点后应提示「敬请期待」。
10. **退出登录**：预测/档案页「退出登录」应清 token 回落地页。

**注意（重点看这些易错点）**：
- 建档**不填经纬度**时，排盘会降级 4 法（占星/七政/奇门/五运六气）——这是预期，档案页应有「已降级」提示；要九法完整必须填经纬度。
- 断前尘/预测是**异步**（后台 LLM），等待可能 10 秒到几分钟，页面应有进度条/等待态，**不要误以为卡死**。
- 校准页「修正」要能输入文字；契合度百分比要能显示。

**通过标准**：10 步全部走通、无白屏、无控制台报错、无 500。

## 阶段 4 · 真实 LLM 输出质量抽检

**做什么**：method-prompts 已自研重写，但**只有 bazi-pattern 真调冒烟过**，其余 8 法未逐一真调。要抽检各法产出的 method-result 是否合法、可溯源。

**怎么做**（逐法跑，看输出）：
```bash
cd C:\Users\wumoh\Documents\Vibecoding\taichu\backend
python -c "import asyncio,json; from app.methods.base import analyze_method; \
s=json.load(open('tests/fixtures/slices/bazi-dayun-liunian.json',encoding='utf-8')); \
r=asyncio.run(analyze_method('bazi-dayun-liunian','duan-qian-chen',s,'事业运势')); \
print(len((r or {}).get('past_propositions',[])), '条命题')"
```
（把 `bazi-dayun-liunian` 换成另外 7 个 key：bazi-shensha-nayin / bazi-hunyin-caiyun / ziwei / xizhan / qizheng / qimen-lifetime / wuyun-liuqi，slice 文件在 `tests/fixtures/slices/` 下同名。）

**注意**：
- 每次真调会花钱（单法约几千～一万多 token），**别一次全跑**，先抽 2–3 个代表性的（如 ziwei、qizheng）。
- 看输出是否：`past_propositions` 非空、每条有 `year_range/domain/claim/confidence_level/basis`、`claim` 具体可证伪、`basis` 能溯源到 slice 字段。

**通过标准**：抽检方法输出非空、结构合法、claim 不空泛、basis 可溯源。

## 阶段 5 · self-run 10× 成本实测（**全项目开发完成后**再做）

**做什么**：量单 case 首跑全盘总成本，回填成本闸门阈值。

**怎么做**：
1. 全项目开发完成后，注册账号 → 完整走一遍（建档[带经纬度]→排盘→断前尘→校准→预测）。
2. 后台日志里每步有 `LLM chat 成功 ... total_tokens=...`；一次完整首跑 ≈ 断前尘 9 分析 + 9 校验 + 预测 5 分析 ≈ 23 次调用。
3. 重复 10 次（不同账号），记录每次总 token，算出单 case 平均成本。
4. 对比技术框架建议阈值（¥0.5–1.0/case），决定 `TAICHU_COST_GATE_MODE`（full / lite / minimal）写进 `backend/.env`。

**注意**：
- 成本**必须计入校验调用**（校验与解读分开，但都花钱）。
- 缓存复用后（同 case 再问）边际成本会大幅下降——首跑成本是锚，不是常态成本。

**通过标准**：拿到 10 次的单 case 首跑成本数据，回填阈值。
