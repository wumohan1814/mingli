## 5. 关键技术经验（沉淀）

### A. **ImageGen image-to-image + input_fidelity 锁定角色一致性**（核心突破）
- 纯文本 prompt 生 10 帧 → 角色严重漂移（本次实测：3 帧分别出现棕/黑/金瞳 + 不同脸型）
- 加 `image: ["<master_path>"]` + `input_fidelity:"high"` 后 → 10 帧角色高度一致
- master 选择标准：与目标形象匹配度最高的一帧（本次选 31-sec 帧：圆脸+打坐+佛珠+墨青袍+暗红披风，仅瞳色黑而非金）
- 副作用**：瞳色锁定为 master 色，与原 mascot 金瞳有"微调"差异（spec 允许"微调表情/姿态"）

### B. **文件名碰撞与"Frame number N." 前缀**
- ImageGen 文件名 = 截断 prompt (~50 char) + 秒级时间戳
- 5 帧共享同一秒级时间戳 → 文件互相覆盖，只存活最后写入的 1 个
- **必加唯一前缀**：prompt 起始加 `"Frame number one." / "Frame number two." / ...` 使截断前缀差异化

### C. **image-to-image 模式 BG 实际色 ≠ prompt 指定色**
- prompt 写 `#E6E2DA` (230,226,218)，实测输出 ≈ (208,199,185) 的暖棕灰
- 用固定 target + 容差抠图 → 一个像素都没抠掉（差 20-33 超 25 容差）
- **改为每帧实际采样 BG 色**作为该帧 key target（容忍帧间色差 ±10）

### D. **水印擦除区域尺寸**
- 双行水印（"AI生成" + "WORKBUDDY"）实际占 22%宽 × 12%高
- 旧值 16%×5% 仅盖下半行 → 6/10 帧水印残留
- 新值 22%×12% 全覆盖

### E. **F2 黑图生成失败**
- image-to-image + high fidelity + 特定 prompt 触发全黑输出（model 偶发失败）
- 解决：换 prompt 措辞重生成（保留 init_image + high fidelity）

### F. **sprite 帧排序必须按帧号非字母序**
- `sorted()` 按文件名字母序 → "eight/five/four/..." 而非 1/2/3/...
- CSS steps() 按此顺序播放 → 动画错乱
- **必须**按帧号数字排序：`def frame_index(fname): for word,num in WORD_TO_NUM: if f'Frame_number_{word}_' in fname: return num`

### G. **WebP 透明保留**
- `Image.new('RGBA', (...), (0,0,0,0))` 透明画布 + `paste(frame_rgba, (x,y), frame_rgba)` 用帧 alpha 作 mask
- 避免 `Image.new('RGB', ...)` 后转 RGBA（alpha 全 255）

### H. **ImageGen transparent 参数偶发生效 + compose.py 需 opaque BG 采样**
- 本次 v2 重绘时，`background: "transparent"` 实际生效，输出 RGBA 透明底
- 但 `compose.py` 的 `process_frame()` 假设 RGB opaque BG（top-center 采样 → 键控 → 出 RGBA）
- 直接喂 transparent RGBA → `convert('RGB')` 把透明当黑色 → top-center 采到角色色（白头髮）→ 键控误删角色
- **修法**：喂 compose 之前先 `precompose`：把 RGBA paste 到 8% padding 透明画布，再合成到暖灰 (208,199,185) RGB 画布，save 为 RGB PNG；top-center 就能采到纯 BG
- 代价：源图从 1024×1024 → 1186×1186，cell 内角色比例略缩；可接受
- **反面教训**：绝不要在同一文件上重复 precompose（1186 → 1374 双 padding），角色会过小；务必从原始 RGBA 一次性填充，或明确每次重置源文件
- 脚本：`.workbuddy/cache/req084-r7/precompose_v2.py`

### I. **input_fidelity:high 跨 prompt 收敛于 master 视觉风格**
- 同一 master 下，多次 prompt 微调（"BOTH HANDS clearly visible" vs "in the lap area"）产出收敛于同一构图
- 想改构图需换 master（但换 master 会带入新风格如金瞳/法盘）
- 实用策略：接受"略近"trade-off，提示词只微调语义（位置/姿态），构图交由 master + input_fidelity:high 锁定

### 10.5 新关键技术经验（沉淀）

### J. **clean_dark_bg.py：ImageGen 黑 BG + 水印的 Pillow 后处理**
- ImageGen `background:transparent` 实际不可靠：本会话 v3 输出纯黑 BG（v1 输出奶油水墨晕染）——模型随风格自动填 BG
- **修法**：角点采样 BG → RGB sum<100 的近黑像素按 ratio 渐变透明（保留字符边缘抗锯齿）→ 右下 22%×12% 水印区直接 alpha=0
- 输出：webp 195KB / png 1.3MB，alpha 四角=0 透明
- 脚本位置：`.workbuddy/cache/req084-r7/clean_dark_bg.py`
- 通用：所有 ImageGen 输出过一遍这道后处理，sprite 即可直接接入

### K. **text-to-image vs image-to-image 的策略选择**
- **image-to-image + input_fidelity:high**：源图与目标风格一致时（国学 sprite 10 帧 → 同风格），跨帧一致性强
- **text-to-image 从零描述**：源图与目标风格错位时（写实 MBTI 源设 → Q版国风定妆），image-to-image 会带歪结构（v1 脸部变黑块）——text-to-image 反而更稳
- **判断标准**：源图与目标视觉风格是否同一家族？同家族 → image-to-image；跨家族（写实→Q版 / 现代→国风 / 油画→水墨）→ text-to-image

- **应急**：cp 到正确目录后改名
- **预防**：并发时复用同一 output_dir，或改为串行调用
