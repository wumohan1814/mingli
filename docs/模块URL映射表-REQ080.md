## 2. 路由规则与约束

1. **单页单 index.html**，不拆多 HTML；前端以 `location.pathname + history.pushState` 切换视图，点导航 `pushState`、无整页刷新。
2. **服务端 SPA fallback**：所有非 `/api`、非 `/vendor` 等静态、非 `/admin` 路径统一回 `index.html`（现机制已具备，落地时审计边界 + 404 兜底）。
3. **静态资源根绝对路径 `/vendor/*`**：沿用 BUG-009 教训，禁止相对路径回归。
4. **兼容深链**：`/mbti/share/:token` 现有分享、`/share/fill/:token` 未来帮填，以及 Agent 等深链统一走此路由，不得破坏既有访问。
5. **旧行为保持**：访问根路径进落地页；刷新停留、前进后退、收藏/复制分享均生效。

## 3. 已确认决策（2026-09-08 需求方拍板）

1. **起卦子法路径**：共用 `/divination`，子法（六爻/梅花/小六壬/观音灵签）走内部 state / 查询串 `/divination?method=liuyao`，**不拆独立子路径**（避免深链碎片化）。
2. **Hub 路径名**：采用 `/guoxue`、`/xishi`、`/mbti`（**不加 `-hub` 后缀**）；功能页 `/jiufa` `/zodiac` `/astrology` `/tarot` `/lenormand`，与后端/Node 路由命名一致。
3. **设置页**：独立 `/settings`（支持深链进入）。
4. **未知/失效路径**：统一回落地页 `/`（可选 toast 提示），不白屏、不做独立 404 页。
5. **历史向后兼容**：做「旧书签/旧链接」的 `pathname` 归一化重定向到新路径（首屏读 pathname 映射），**不产生死链**。

## 4. 落地口径（给前端 F4 的实现备注）

- 各路径 → 现有 `navigate({"p":<主模块>, "p2":<子视图>})` 的绑定，由 F4 在实现时按最终确认版逐项落表并回填本行备注；`pushState` 写入真实 path，`popstate` 反向解析回视图。
- 埋点/GA 后续如需「页面浏览」事件，可在此路由层挂 `track('page_view', {path})`（不在 REQ-080 内，作为可选扩展）。
