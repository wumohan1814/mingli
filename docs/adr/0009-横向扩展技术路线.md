# ADR-0009: 横向扩展技术路线（复用 mingyu-core + 确定性免费 / LLM 可选付费）

## Status

Accepted（2026-09-06）

## Context

- 产品规划 §2.2/§7.2 要求补齐横向扩展：生肖 · 临时起卦（六爻/梅花/小六壬/大六壬/金口诀/奇门时家/观音灵签）· 星座 · 塔罗 · 雷诺曼 · MBTI。
- 现有 9 法主线（国学预测）已上线；横向扩展是「在现行业务上做加法」，不得回归主线。
- `backend/paipan-node/vendor/mingyu-core/dist/` 已内置上述全部确定性引擎 + 中文文案（塔罗/生肖/占星/起卦/雷诺曼），且 `package.json` 已含 `mingyu-core` 依赖。

## Options

| # | 议题 | 方案 A（选用） | 方案 B（弃用） |
|---|---|---|---|
| D1 | 引擎路线 | 复用已内置 `mingyu-core`（全量覆盖 + 中文） | 引入 kerykeion / astrology-js / tarot-js / libarcana（子集或英文版） |
| D2 | MBTI 路线 | 纯代码计分 + 自备题库/文案（零 LLM） | 依赖外部仓库运行时 / LLM 判型 |
| D3 | 星座盘型 | 本命 + 行运 + 日返 + 次限（+太阳弧白送），法达自研查表 | 三限/月返/日互（砍掉，置灰） |
| D4 | LLM 边界 | 确定性计算零 LLM 零扣费；「串成解读」才调 LLM 且可选付费 | 全程 LLM 解读 |
| D5 | 付费点 | 沿用现有积分（1 积分=1000 tokens、即时扣费、check_balance 拦截） | 新计费体系 |
| D6 | 信息架构 | 主页收敛三大入口；国学/西式各自插入 HUB 页 | 平铺入口 |
| D8 | 数据落库 | 新增 4 表（tarot/astrology/mbti/divination），`user_id` 行级隔离进 analytics 库 | 复用 cases 表混存 |

## Decision

采纳方案 A（D1–D8），另定 5 项执行决策：

1. **interpret 付费沿用「按 token 即时扣费」**（ref：`tarot:{id}` / `divination:{id}` / `astrology:{id}`），缓存命中零扣费。
2. **MBTI 题库上标准版 60 题**（非 28 题简版）。
3. **塔罗卡面先占位**（卡名 + 花色 + 正逆位翻转 CSS/SVG），美术由用户另行生成后装配（D7）。
4. **起卦/占卜类目合规沿用**现有「娱乐化定位 + 免责声明 + 不承诺结果」护栏（`compliance/guardrails.py`）。
5. **后台 Phase2 专用端点留端口不实现**（`GET /admin/users/{id}/{tarot-readings|astrology-readings|mbti-results|divinations}` 固化路径约定，MVP 不注册）。

MVP 起卦范围：六爻 / 梅花 / 小六壬 / 观音灵签（大六壬/金口诀/奇门时家 Phase2）。

## Consequences

### 变得更容易
- 零新增 npm 依赖，复用双运行时 + LLM 客户端 + 积分 + 埋点四件套，边际成本趋零。
- 确定性计算免费成为 Freemium 引流钩子（生肖/抽牌/起卦/星盘/判型全免费）。
- 新增 `*/interpret` 端点是现有 `revise`/`query` 计费模式的复制，实现成本低。

### 变得更难
- 前端页面数量显著增加（两个 HUB + 6 个模块的流程页 + 结果页），需分 Phase 迭代。
- MBTI 60 题题库 + 16 型文案内容建设量大，需多源改写规避版权（16personalities 等）。
- 塔罗卡面美术缺失期体验差，需 CSS/SVG 占位过渡。
