# ADR-0008: JWT 算法采用 HS256，Phase2 视需要升级 RS256

## Status

Accepted（2026-09-05）

## Context

- R7 定为 JWT 无状态令牌（短访问 15–30min + 刷新 7d），审查报告将「JWT 算法 (HS256/RS256)
  与密钥轮换」列为**实现期遗留项**，未决。
- MVP 为**单进程单实例**部署（R8 / C24），不存在多服务验签场景。
- 用户已选择强制注册（ADR-0007），鉴权是 MVP 的必经路径，算法需先定。

## Options

| 方案 | 描述 | 优点 | 代价 |
|---|---|---|---|
| **A** | **HS256（对称签名）** | 实现最简、验签快、密钥单一；MVP 单实例无分发问题 | 密钥轮换需所有实例同步；密钥泄露即全局可伪造 |
| B | RS256（非对称） | 验签方可只读公钥，轮换容易；多服务场景更安全 | 密钥对管理复杂；MVP 单实例下收益不显 |

## Decision

选择 **A（HS256）**，密钥走环境变量 `TAICHU_JWT_SECRET`，不入库、不入库代码。

- 配套要求：密钥随机生成、长度 ≥ 32 字节；不同环境使用不同密钥；泄露时全量失效并重登。
- 升级触发条件：**模块拆分为多进程 / 多实例（Phase2，技术框架方案 §12.7）时**，
  或引入第三方验签方时，升级为 RS256 并配套密钥轮换机制。
- 短访问令牌（15–30min）已限制泄露窗口，这是 MVP 阶段的主要缓解手段。

## Consequences

### 变得更容易
- 实现最简，无需密钥对管理与分发。
- 验签性能好。

### 变得更难
- 密钥轮换是"全量切换"，需短暂停服或双密钥过渡期。
- 密钥泄露的影响面是全局的（可伪造任意用户）——已被短令牌 TTL 部分缓解。
