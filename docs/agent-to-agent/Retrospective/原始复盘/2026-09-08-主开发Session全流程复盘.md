# 主开发 Session 全流程复盘（可跨项目复用）

> 会话：主开发（需求编排 / 派单 / 审查 / git / 部署）
> 周期：2026-09-06 → 2026-09-08（多轮目标驱动开发，跨 checkpoint）

## 一、检索范围说明（先说清能看到什么）

- **可直接访问**：本会话完整对话（checkpoint 恢复后）+ 压缩交接摘要（checkpoint 前的关键事实：目标、REQ/Bug 台账、决策、协作约定）。可确认的具体事件均来自这两者。
- **只能间接看到**：文字/美术/测试/台账等并行 Session 的**产物**（git 提交、docs 交付、需求表/Bug表备注更新）——通过共享 git 工作区观察，看不到它们的过程对话与中间推理。
- **无法访问 / 内容缺失**：其它 Session 的私有对话、部分早轮细节（早于压缩点的原始会话正文）。凡此均未臆测，以下经验只从可确认现象提炼。
- **适用对象**：同一用户 + 主开发编排角色 + code_flash 子 Agent 的协作模式；内容已剥离 taichu 专属细节。

## 二、经验清单（现象 → 根因 → 可复用规则 → 落地检查项）

### A. 架构设计（踩坑代价最高）

**A1.【S0】巨型单文件 → 子 Agent 停滞/自检循环崩溃**
- 现象：15000+ 行单文件 index.html，6 项任务的一次派单 16 分钟**零写盘**（中断）；缩到 2 项后 Agent 仍陷入"再读一遍 / 再自查一遍"循环直到失败。
- 根因：超大文件迫使 Agent 反复 grep/read 灌满上下文；无终止条件的自我验证循环耗尽轮次；任务粒度与文件规模不匹配。
- 规则：大单文件场景，子 Agent **每批 ≤2 项**；prompt 强制"先 grep 定位锚点再精准 read，禁止整文件通读"+"**只跑一次** node --check 即停报告"；必要时在 prompt 给出锚点函数名/行号区间省去定位。
- 检查项：本批任务数 ≤2？prompt 是否含反过度自检句？是否有明确锚点？

**A2.【S0】全局横切决策不先拍板 → 返工面巨大**
- 现象：路由（17 路径）、计费（积分→余额、1 元=1 万 tokens、展示 balance/10）等全站口径，若后改会推倒大片实现；先产出"映射表/契约 + 决策清单"让需求方拍板后才动工，全程零返工。
- 根因：横切决策（路由/计费/命名/数据模型）牵一发动全身。
- 规则：实现前先产出**契约文档 + 显式决策清单**，需求方逐项确认；把确认结论**写入台账备注**作为现行约束（开发实现时以备注为唯一口径）。
- 检查项：是否存在待拍板横切项？决策是否已固化进台账/契约？

**A3.【S1】"结构先上、正文后补"若不做接入跟踪 → 占位符长期裸露**
- 现象：三关系按钮先上，792 对文案正文留"文案待补充"空表；素材交付后未安排接入轮次，界面残留占位成为验收缺口。
- 根因：结构与内容分离推进，但交付→接入之间没有显式闭环。
- 规则：任何"先上"都登记为**显式跟踪项**（含责任人/轮次）；交付物（文案/美术）附带"接入待办清单"；发布前用 grep 占位文案兜底核查。
- 检查项：占位符/空表清单是否清零或有排期？交付回执是否列了接入待办？

**A4.【S1】台账备注高频修订（v2/v2.1/二次确认）→ 用旧口径实现**
- 现象：需求反复在备注修订口径（必填→可选、范围拆分），按旧正文实现即错。
- 根因：活文档迭代快，无版本化但备注是权威。
- 规则：实现前**读最新备注**；代码注释挂 REQ 编号 + 关键口径，便于回溯。
- 检查项：是否按台账最新备注实现？改动是否回填备注？

**A5.【S2】后端多文件可并行、前端单文件必串行**
- 现象：两个后端 Agent 并行、任务边界清晰时成功率 100%；前端单文件一旦并发即冲突。
- 根因：文件依赖决定并行度。
- 规则：并行边界 = **文件所有权**不相交；单文件永远是流水线（一批完成即提交，再派下一批）。
- 检查项：并行 Agent 的文件集合是否两两不相交？

### B. 协作协议（多 Session / 多角色）

**B1.【S1】共享工作区无锁 → 并发编辑/断点丢注册**
- 现象：另 Session 并发改同一台账，主会话 edit 报"file changed since read"；checkpoint 后后台 job 注册表清空，B2 显示 running 实为文件正在被写（以磁盘为准才判断正确）。
- 根因：git 工作树是唯一通道，无锁；会话断点不保留后台任务注册。
- 规则：编辑共享文档前**必 re-read**；每 Session 只碰自己的产物文件；**断点恢复先核对磁盘/文件实际状态，不信任 job 注册表**；后台任务用 durable agent id 追踪（list_agents），或直接看文件 mtime/diff。
- 检查项：目标文件当前是否被别人改动？恢复会话后先 git status / 文件 diff 再决策。

**B2.【S1】网络代理：git/curl 与浏览器不同源**
- 现象：浏览器能连 GitHub（走 VPN 系统代理），git push 却失败——git 配置了过期 LAN 代理，且覆盖为空(直连)也被 GFW 重置。
- 根因：git/curl 不读浏览器代理；VPN 常以系统代理形式存在（WinINET），git 不感知。
- 规则：push 不通先查系统代理：`reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`（ProxyServer），再用 `git -c http.proxy=<系统代理> -c https.proxy=<系统代理> push` 实测；不要信"VPN 开了"这种进程级前提。
- 检查项：本次 push 用哪个代理？是否先实测再批量重试（避免 21s×N 空等）？

**B3.【S2】停滞 Agent 无阈值管理 → 白等数轮**
- 现象：某 Agent 多轮零输出仍显示 running；手动 interrupt + 缩小重派（6→2 项）后成功。
- 根因：无停滞判定与介入机制。
- 规则：给任务设**停滞阈值**（大文件前台任务 >10–15min 零写盘即判停滞）；中断前确认磁盘无半成品（可安全放弃）；中断后保留 agent（ready）可 re-scope 复用，或直接新派小批。
- 检查项：Agent 运行时长？是否产出？要不要 interrupt + 重派？

**B4.【S2】提交/台账由单一角色总负责**
- 现象：各 Session 产物散落，由主开发统一 commit（每批即提交）+ 台账回填（🟡/🔵→🟠），冲突少、历史干净。
- 根因：git 操作权收敛到一个角色。
- 规则：明确"谁提交"；开发批完成即提交（可随时回退/串行下一批），文档/台账由指定方统一收口。
- 检查项：当前未提交变更属于谁？批与批之间是否已 checkpoint？

### C. 工作定义（角色 / 目标 / 约束 / 中断恢复）

**C1.【S0】铁律前置定义决定协作效率**
- 现象：用户开局即定"主会话不写码（全交子 Agent）/ 同型相关→单 Agent、细碎无关→多 Agent / 子 Agent 干活时可直接停会话等通知 / 多 Agent 须文件无冲突 / 省 token 优先"。全程无越界、无重复劳动。
- 根因：角色、分工、等待机制、资源优先级在启动时固化。
- 规则：启动即写死：①谁写码/谁审查/谁提交；②禁止事项（主会话不写码、单文件串行）；③任务粒度与并行的文件边界；④等待=停会话，不轮询。
- 检查项：见下"下一项目启动检查清单"，逐条打钩。

**C2.【S1】验收角色分离：开发完成≠验收通过**
- 现象：状态机 🟡→🔵→🟠→🟢，🟢 仅测试组可设；开发完成只置 🟠（待验收），避免自证自验。
- 根因：开发与验收同角色会掩盖缺陷。
- 规则：用状态机 + **唯一验收方**；开发侧只推进到"待验收"，把"谁验收、怎么验"写进条目。
- 检查项：完成项是否只置 🟠？验收方与口径是否明确？

**C3.【S2】中途新增需求是常态 → 当独立工作包管理**
- 现象：多轮中途追加（批量新 REQ/Bug、临时加"安装到桌面"按钮），若并入当前批会失控。
- 根因：需求流动不止。
- 规则：新增项按优先级（P1/S1）排队成新批，不与在制批混合；先全量读台账拿完整清单再排程，避免漏项/返工。
- 检查项：有没有漏读的新条目？排程是否按优先级？

**C4.【S2】目标驱动需显式完成判据**
- 现象：长任务以 goal（可续跑轮次）承载，明确"完成 = 代码落地 + push + 部署 + 健康检查 + 台账回填"，据此判定结束，不靠感觉。
- 根因：无完成判据则无法收敛。
- 规则：长任务定义**可验证的完成判据**（文件/测试/部署/台账），逐项取证后才标 complete。
- 检查项：判据是否全部满足且可出示证据？

## 三、下一项目启动检查清单（开跑前逐条打钩）

1. **角色铁律**：□ 谁写码（子 Agent）谁审查（主）谁提交（git 单一负责）；主会话禁止写码已写明。
2. **台账单一事实源**：□ 状态机（🟡→🔵→🟠→🟢）与唯一验收方已定；开发完成只置 🟠。
3. **横切决策前置**：□ 路由/计费/命名等全站口径先出契约文档+决策清单，需求方拍板后写进台账备注。
4. **文件所有权与并行边界**：□ 列出所有将并发修改的文件，两两不相交；单文件（如 index.html）明确串行 + 批间提交。
5. **子 Agent 任务规范**：□ 每批 ≤2 项；prompt 含"grep 定位 + 精准 read + 只验一次 + 立即报告"；提供锚点；设定停滞阈值（>10–15min 零产出即 interrupt 重派小批）。
6. **共享文件纪律**：□ 编辑前必 re-read；每 Session 只碰自己产物；恢复会话先核对磁盘实际状态，不信 job 注册表。
7. **网络/代理预案**：□ 启动即从系统注册表读代理并实测 push，固化正确的 `-c http.proxy=`；不盲信"VPN 已开"。
8. **素材/文案交付闭环**：□ 交付物附接入待办；"结构先上"项登记正文接入轮次；发布前 grep 占位符兜底。
9. **中断与恢复**：□ 子 Agent 工作即停会话等通知（不轮询）；目标驱动任务有可验证完成判据，逐项取证后收敛。
10. **优先级队列**：□ 中途新增需求一律按 P1/S1 排队成新批，不与在制批混合。
