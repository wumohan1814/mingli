# 太初产品规划 · 诊断与规划文档

> 文档定位：将"命理 Skill → 线上 H5 产品"的想法，从模糊设想收敛为可执行的 MVP 规划与合规框架。
> 撰写视角：产品诊断（AI 刘小排 office-hours 沉淀）+ 项目规范化补充。
> 状态：第一阶段规划稿，含 2 项待调研开放问题（见第 8 节）。
> 日期：2026-09-05 ｜ 更新：2026-09-06（支付通道决策改为"小微商户码优先 + 升级阈值"）｜ 更新：2026-09-08（补充 §6.4「实现现状」，本轮功能均已上线）

## 1. 项目背景与目标

- 现状：已有自研"命理"Skill（排盘 + 命理演算），原作为 OpenClaw 体系下的能力模块。
- 目标：将 Skill 细化为可上线的独立产品。第一阶段由 Skill 演化；第二阶段横向扩展（单手法独立化、生肖 MBTI、星座塔罗等）。
- 形态约束：
  - 不做 APP、不做微信小程序（规避平台审核与类目限制）。
  - 仅做线上 H5。
  - 不采用重型 Agent 框架（如 OpenClaw 类），使用轻量包装层。
  - 每个用户进入后拥有独立 session，自主完成算命流程。

## 2. 目标客群

### 2.1 主客群画像（第一阶段验证对象）

- 代号：王姐（化名）。
- 特征：35 岁女性职场员工，面临失业，希望通过命理获得"何时找到下一份工作"的方向感与情绪安抚。
- 痛点属性：事业运势焦虑为"现在进行时"，具备当下代价（收入中断、面子、生活压力），痛感强、频次高。
- 现状凑合方案：市面人工算命（不可靠、师傅擅长方向不一、需预约、不便）。

### 2.2 客群分野（关键判断）

- 选择 AI / 线上自助算命的用户，与找人工师傅的用户**不是同一批客群**。
- 前者偏好"自助、全套、随时可问"的产品形态；后者偏好"人"的权威感与互动。
- 推论：本产品的客群**只在"全套自助产品形态"成立时才存在**。因此 MVP 必须以产品形态本身获客；用"人工咨询链接"做验证会引入错配客群，结论无效。
- 市场已被教育：AI 算命赛道已有大量成功付费案例，付费意愿无需重新验证；待验证的是本产品的单位经济与差异化获客（见第 5、8 节）。

## 3. 产品定位与核心卖点

### 3.1 核心差异化（10x 优势）

- 多流派综合：八字 / 紫微 / 六爻等并行，单个人工师傅通常只精一种。
- 可修正：用户补充信息后结果可迭代收敛，更接近用户预期的"准"。
- 随时问：线上服务，突破预约与时空限制。
- 落地页主张应为：**"多种流派综合 + 可修正 + 随时问"**。

### 3.2 卖点表述红线

- 不主打"AI 新颖"：命理信任来自神秘感 / 权威感 / 被懂，AI 标签在命理心智中属减分项。
- 不承诺"准"：命理本质模糊，承诺"准"双向受损——用户觉不准则信任崩；监管上承诺预测具体结果近踩线。
- 采用"趋势 / 参考"话术，不输出确定结论。

### 3.3 内容定性（合规与传播）

- 对外称谓：命理文化 / 国学运势 / 事业运势分析（避免"算命"二字）。
- 禁区：不涉医疗、投资、司法预测。
- 示例改写：王姐的"什么时候找到工作" → "事业运势趋势参考"。

## 4. 合规与部署策略

### 4.1 风险归约

- 监管 / 法律风险的关键不在"服务器物理位置"，而在三要素：**收款主体、支付通道、内容定性**。服务器位置仅影响访问速度与管辖。

### 4.2 服务器部署

- 建议：香港 / 新加坡轻量节点（国内访问延迟低、免 ICP 备案、内容管辖较宽松）。
- 避免：美东等远距离节点（访问慢）。
- 与"轻量包装、不用重框架"的调性一致。

### 4.3 支付通道（最硬风险）

- 形态约束：用户模型为"积分 = token 消耗"预付费（买积分包 → 推演消耗），需支付成功回调以自动加积分；用户不希望额外注册。产品为**纯线上虚拟服务，无实体店面**。
- 真裸奔（不推荐）：纯个人微信 / 支付宝转账码直收。① 259 号文明确"个人静态收款码禁止用于远程非面对面收款"，H5 线上收款正属禁区；② 无支付回调 API，无法自动核销积分；③ 无主体，被风控冻结后零申诉通道。
- 免费个人经营收款码（小微商户）的硬门槛：**申请强制要求"经营场景照片"，类型仅"固定门店 / 移动摊贩"二选一，无"纯线上服务"类目**。该路径是监管为地摊 / 实体小微设计的，不覆盖无实体店面的线上算命 H5。强行以"摊位照"过审属掩耳盗铃，且不解决命理类目风控。故免费个人经营码**非本产品干净方案**。
- 纯线上服务的现实轻路径（二选一）：
  - **小金商户助手（金数据）**：走持牌通道，**个人凭身份证即可申请、不要求固定经营场所**；明确支持线上虚拟 / 服务 / 知识付费 / 咨询。一张表单即"产品页 + 收款 + 订单 + 客户档案"，贴合需 user / session 数据沉淀的模型。持牌主体为金数据，**个人商户侧无需营业执照 / ICP 备案 / 固定场所，仅身份证 + 个人银行卡 + 人脸核验**——即"借持牌平台"的聪明裸奔路径，个人无备案亦可合规收款。
    - 集成深度（两种模式）：① **零代码半自动**——H5 充值按钮跳小金收款页 → 用户选档位付微信 / 支付宝 → 订单自动落金数据后台，人工 / 导出对账；② **API 全自动**——金数据开放平台提供 **Webhook + API v1（全套餐开放）**，且支持"URL 传参"携带 user / session 标识，支付成功事件可回调后端**自动按用户加积分**（"提交表单后网页跳转回 H5"需专业版及以上）。故"弹二维码收款 + 支付后自动走订单加积分"均可实现，并非只能人工。
    - 实测口径（2026-09 官方）：费率 **1.49%**（个人商户有 1% 补贴活动）；资金 **个人 D+5 / 企业 D+1** 结算到绑定银行卡；月交易限额 **个人 / 个体户 60 万**；免费版月收款额度 **500 元**，放大需专业版。
    - 代价：约 1–1.49% 费率 + 第三方依赖 + 资金结算节奏偏慢（个人 D+5）。MVP 最贴合的轻合规解。
  - **个体工商户商户号**：注册个体户（经营范围写"文化咨询 / 软件开发 / 信息技术服务"，不写命理、无需实体店面），自当微信 / 支付宝商户，拿真实支付回调 API、无抽成、资金直达。代价：注册 + 税务申报。起量或需强回调 / 开票时的最干净解。
- 升级阈值（监管预警线，非罚款线）：月流水稳定 < 约 1 万（连续 3 个月未破 10 万线）→ 安全甜区，小规模纳税人月销 10 万下免增值税；**连续 3 个月月均超 10 万（经营行为判定 + 增值税线）或需信用卡 / 更高限额 / 开票 → 转个体户**。其他红线：支付风控单笔 3-5 千 / 日累 1-5 万 / 月累 5-30 万；个人码年累计 120 万强制升级；反洗钱单日 5 万上报。
- 残留风险：命理类目在微信 / 支付宝仍可能被限流（若判禁售）；全站需做"娱乐化定位 + 免责 + 不宣称精准"包装（见 3.3）。
- 阶段决策：MVP 用**小金商户助手**跑（线上原生、免实体、带订单数据）→ 月均破 10 万转**个体工商户**商户号（去抽成、拿 API、去第三方）。

### 4.4 传播风险

- 微信内分享 H5 可能被限流 / 封链接；无主体时无可申诉。
- 缓解：内容定性合规 + 不依赖单一分享通道 + 裸奔阶段不投入重内容资产（避免一封归零的沉没成本）。

## 6. 第一阶段 MVP 规划

### 6.1 范围

- 后端：由全 Skill 演化（用户决策，验证成本低）。
- 前端入口：需设主场景钩子（失业找工作 / 事业运势）作为默认路径；避免"什么都能算"的落地页（转化最低）。
- 第二阶段素材（感情 / 财运 / 生肖 MBTI / 塔罗）不进第一阶段前端，避免分散火力。

### 6.2 架构即成本

- 排盘、演算为确定性计算（规则引擎），应本地 / 边缘执行，**不每次调用 LLM**。
- 仅"自然语言解读 + 用户修正对话"调用模型。
- 该拆分直接决定 token 费用量级（差异可达十倍），需在架构设计阶段固化。

### 6.3 最小闭环与优先级

- 闭环：输入生辰 → 排盘 → 输出综合解读 → 支持一轮修正对话。
- 交付优先级高于获客：先自建闭环，自行跑 10 次，量出单次 token 成本，定价才有底。

### 6.4 实现现状（2026-09-08）

- **MVP 本体与横向扩展已全部开发上线**：MVP（断前尘 / 预测 9 法主线）与横向扩展模块（生肖流年 / 临时起卦 / 塔罗 / 雷诺曼 / 星座 / MBTI）均已实现。
- **计费已从「积分」切换为「余额 ¥」**：积分概念全站废除，余额与 Token 直接绑定——1 元 = 10,000 tokens（展示层 `balance_yuan = round(balance/10, 2)`），注册赠送 22 元（见 `docs/架构设计.md` §9 余额系统（REQ-085））。
- **本轮新增功能已上线**：PWA 可安装（REQ-098）、八字配对（REQ-093④）、八字/九法起名（REQ-094）、分享帮填（REQ-070）、真实子路径路由（REQ-080）、新用户建档强制门（REQ-092）。

## 7. 补充思考（诊断外延展）

### 7.1 留存与复购

- 算命单次低频，但事业运势因失业 / 换岗 / 晋升焦虑而反复触发，属相对高频场景。
- 需设计回访节点（月度运势、关键决策点触达），否则单位经济外的第二大商业变量（LTV）不成立。

### 7.2 数据资产

- 每用户独立 session + 生辰 + 历史对话 = 可累积的命理档案。
- 该档案是第二阶段横向扩展（生肖 MBTI / 塔罗打通）的数据底座，也是差异化护城河。
- "独立 session"不止是技术形态，是长期数据资产起点。

### 7.3 技术形态建议

- 静态 H5 + 轻函数后端（边缘函数 / Serverless），session 无状态化（token 鉴权）。
- 与"不用重 Agent 框架"一致，且利于香港节点低延迟部署。

### 7.4 获客渠道（待后续轮次）

- 客群偏好"AI 自助算命"，聚集于抖音 / 小红书"B 型"内容（非人工咨询向）及微信内。
- 获客策略留待客群与单位经济验证后细化。

## 8. 待调研开放问题（用户确认需调研后回答）

- **Q1（差异化获客）**：市面已有成功 AI 算命案例，其定价与单位经济结构如何？本产品"多流派综合 + 可修正"凭什么将用户从现有案例切过来？
- **Q2（差异化溢价）**：用户的"全套"卖点，凭什么让用户愿意比免费 / 低价案例支付更高价格？
