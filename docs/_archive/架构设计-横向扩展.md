## 4. 技术路线总览

### 4.1 复用现有双运行时
- Python 侧（FastAPI）：路由 / 鉴权 / 落库 / 积分 / 埋点 / LLM 编排（现有 `app/`）。
- Node 侧（`paipan-node/server.mjs`，常驻 :9317）：排盘与起卦**确定性计算**。新增端点即可，**不新增 npm 依赖**（`mingyu-core` 已在 `package.json` 且已 vendor 完整构建产物）。

### 4.2 新增 Node 端点（`paipan-node/server.mjs`）
在现有 `handleRequest` 的 if/else 链中追加（body 均为 UTF-8 JSON，出错非 200 供 Python 降级）：

| 端点 | 输入 | 输出 | 底层调用 |
|---|---|---|---|
| `POST /zodiac` | `{zodiac:"鼠", year:2026}` | 犯太岁/太岁星君/贵人/五行/行动信号 | `calculateZodiacYearFortune` |
| `POST /tarot` | `{spreadType:"three", interactiveSamples?:number[]}` | 牌阵名 + cards[]（name/position/reversed/keywords/element/archetype）+ draw | `drawTarotSpread` |
| `POST /astrology` | 同现有 `/extra` 的出生信息 + `{scope, dateStr}` | `{natal, fullScope:{natal,yearly,monthly,daily}}` | `generateAstrolabe` + `buildAstrolabeFullScopeContexts` |
| `POST /divination` | `{method:"liuyao"|"meihua"|"xiaoliuren"|"liuren"|"jinkoujue"|"qimen"|"ssgw"|"lenormand"|"almanac", customDate?, options?}` | 对应卦象/课式/签文 JSON | 见 §2 表 |

> 实现纪律：与现有 `/ziwei` `/extra` 一致——常驻 HTTP 优先；`extra.mjs` 原样保留 subprocess 降级路径（新端点是否做降级脚本，按 §11 里程碑决定，MVP 可只走 HTTP）。

### 4.3 Python 侧新增路由（`backend/app/api/`）
每个模块独立 router，注册进 `backend/app/main.py` 的 `include_router` 段：

| 路由文件 | 端点 |
|---|---|
| `api/zodiac.py` | `POST /api/zodiac/fortune`（确定性，**不落库**或落 events） |
| `api/divination.py` | `POST /api/divinations`（起卦，需 `case_id`，落库；雷诺曼 `method="lenormand"` 复用此端点、无需 case_id）、`GET /api/divinations/{id}`、`POST /api/divinations/{id}/interpret`（可选 LLM 断卦/深度解读，即时扣费） |
| `api/tarot.py` | `POST /api/tarot/draw`（落库）、`GET /api/tarot/readings/{id}`、`POST /api/tarot/readings/{id}/interpret`（可选 LLM 综合解读，即时扣费） |
| `api/astrology.py` | `POST /api/astrology/chart`（确定性，落库）、`GET /api/astrology/charts/{id}`、`POST /api/astrology/charts/{id}/interpret`（可选 LLM 本命解读，即时扣费） |
| `api/mbti.py` | `GET /api/mbti/questions`、`POST /api/mbti/score`（纯代码判型，落库）、`GET /api/mbti/results/{id}`（**零 LLM**） |

### 4.4 LLM 端点统一契约
所有 `*/interpret` 端点走现有 `app/llm/client.py`（`chat(json_mode=True, max_tokens=settings.llm_max_tokens)`）+ 现有 `check_balance` 预检 + 即时扣费（对齐 `revise`/`query` 的计费模式），失败按已消耗 token 扣。**缓存命中零 LLM 不扣费**（复用 `method_results` 式缓存思路，键 = 模块 + 输入指纹 + 解读类型）。

## 5. 分模块方案

### 5.1 国学预测 HUB 页
- 纯前端新增一个页面状态（`page='guoxue-hub'`），三个卡片：九法合一（走现有 onboarding/档案 flow）、生肖流年、临时起卦。
- 生肖/起卦需要登录态；起卦额外要求「存在国学档案」，否则提示先建档。

### 5.2 生肖流年（100% 确定性，零 LLM，零扣费）
- `POST /api/zodiac/fortune` → Python 转发 Node `/zodiac` → 返回结构化结果直接渲染。
- 结果字段（由 `calculateZodiacYearFortune` 提供）：`zodiac`、`yearGanZhi`、`yearBranch`、`taiSui.star`（值年太岁星君）、`conflicts[]`（值/冲/刑/害/破太岁 + desc）、`noble`（六合/三合贵人）、`relation`（年干五行 × 生肖五行）、`actionSignals[]`。
- 定位：**免费引流钩子**（注册即用），不扣积分，符合产品规划 Freemium。

### 5.3 临时起卦（确定性起卦免费 + LLM 断卦可选付费）
**选型与优先级**（MVP 先做前 4 个，其余 Phase 2）：

| 方法 | 起卦 seed | 难度 | MVP |
|---|---|---|---|
| 六爻 `liuyao` | 报数 / 摇卦（前端硬币交互）/ 时间 | 中 | ✅ |
| 梅花易数 `meihua` | 时间 / 报数 | 低 | ✅ |
| 小六壬 `xiaoliuren` | 月·日·时（当前时间） | 低 | ✅ |
| 观音灵签 `ssgw` | 随机抽签 | 低 | ✅ |
| 大六壬 `liuren` | 时辰 | 高 | Phase2 |
| 金口诀 `jinkoujue` | 时辰 | 高 | Phase2 |
| 奇门时家 `qimen(scope='hour')` | 时辰 | 高 | Phase2 |

> 注：`择日 almanac`（选吉日）为纯国学工具，非「起卦预测」，本方案作为 Phase2 国学工具单独评估，不混入起卦列表；`雷诺曼 lenormand` 属西式占卜，归入 §5.4 西式 HUB。

**流程**：选已有 case → 选起卦方式 → （六爻/梅花）前端收集报数/摇卦 → `POST /api/divinations`（Node `/divination` 确定性起卦，落库关联 `case_id`）→ 渲染卦象/课式（免费）→ `[可选] 断卦` 触发 `interpret`（LLM，注入 chart 摘要 + 卦象，即时扣费）。

### 5.4 西式占卜 HUB 页（星座 / 塔罗 / 雷诺曼）
- 纯前端新增一个页面状态（`page='xishi-hub'`），三个卡片：星座预测、塔罗牌、雷诺曼；第四个「其他西式占卜」卡片置灰「敬请期待」。
- 星座/塔罗需登录态；各自档案体系独立（星座档案存出生信息、塔罗档案存抽卡记录）。

### 5.5 塔罗牌
- **抽牌（免费零 LLM）**：`POST /api/tarot/draw` → Node `/tarot` 的 `drawTarotSpread`。前端用 `interactiveSamples`（逐张翻牌：每张两张随机样本 = 选牌 + 正逆位）实现「一张张翻牌」的交互仪式感。
- **牌义速览（免费）**：cards[] 自带 `keywords`（逗号分隔）、`element`（火/水/风/土/大阿卡纳）、`archetype`，直接渲染，不走 LLM。
- **综合解读（可选付费）**：`POST /api/tarot/readings/{id}/interpret`，system prompt 用 `buildTarotSpreadTask()` 输出框架 + 用户问题 + 牌阵结果，一次调用、即时扣费。
- 牌阵：MVP 开放 `single/three/love/career/decision`（对应流程图「单张/三张/十字/宾主位」的落地映射），其余牌阵（celtic/year/twelveHouses 等 11 种）已在库内、UI 后续按需放开。

### 5.6 星座预测（盘型已收敛）
- **确定性星盘（免费零 LLM）**：`POST /api/astrology/chart` → Node `/astrology`，返回 `natal` + `fullScope`。
  - 本命盘（natal）：行星/四轴/宫位/相位/庙旺陷落/元素模式（复用现有 `xizhan` 数据结构）。
  - 流年/流月/流日（yearly/monthly/daily）：行运 + 日返 + 次限 + 太阳弧（`astrolabe-scope` 现成）。
  - 法达（firdaria）：**自研纯查表**——75 年法达主限序列（月→水→金→日→火→木→土）按出生日月（日盘/夜盘）起算，约 30–50 行 Python，零依赖。
- **深度解读（可选付费）**：`POST /api/astrology/charts/{id}/interpret`，LLM 聚焦太阳/月亮/上升 + 重点相位串成性格叙事（复用 `xizhan.md` prompt 思路改写）。
- **盘型 UI 映射**（对应流程图）：天象=yearly/monthly/daily 行运、本命=natal、行运=transit、日返=solar return、次限=secondary progression、法达=firdaria（自研）。**三限/月返/日互置灰「敬请期待」**。

### 5.7 雷诺曼
- **抽牌（免费零 LLM）**：复用 `drawLenormandSpread(spreadType, options)`（36 张小牌，库内已含牌义/组合语义），Node 端点并入 `/divination`（`method:"lenormand"`）或单列 `/lenormand`（实现时任选，建议并入 `/divination` 减少端点）。
- **关键词组合解读（确定性）**：牌面自带关键词/主题，前端按「牌位 + 关键词 + 相邻牌组合」做确定性组合文案，不走 LLM。
- **深度解读（可选付费）**：`POST /api/divinations/{id}/interpret`（与起卦共用 interpret 通道，`method="lenormand"` 走西式 prompt）。
- 牌阵：MVP 开放单张/三张/九宫格，其余牌阵 Phase2。

### 5.8 MBTI 人格测试（纯代码，零 LLM）
- **事实源与内容建设**（用户决定：不依赖仓库、全面搬运线上内容）：
  - 机制：四维二分（E/I、S/N、T/F、J/P）为荣格理论公共知识，**自研计分**。
  - 题库：参考开源实现 [lizhijun/mbti](https://github.com/lizhijun/mbti)、[rojcode/mbti](https://github.com/rojcode/mbti) 的题型与计分口径，**改写为自有中文题库**（建议 28 题简版 + 60 题标准版两档）。
  - 16 型文案：综合 [知乎·荣格八维](https://zhuanlan.zhihu.com/p/96952287)、[lucaluo MBTI 简介](https://www.lucaluo.com/mbti-introduction/) 等多源**改写**（优势/盲点/职场/关系/成长建议五栏），标注来源、不逐字复制单一商业源（规避 16personalities 版权）。
- **数据落地**：`backend/app/mbti/questions.json`（题库）+ `types.json`（16 型文案）+ `scoring.py`（判型）。
- **端点**：`GET /api/mbti/questions` → 前端逐题四选一 → `POST /api/mbti/score`（纯代码算分 → 4 字母 + 维度分）→ `GET /api/mbti/results/{id}`。
- **零 LLM**：判型、维度图、类型文案全部本地；**预留**（不实现）「MBTI × 国学命盘」跨读 LLM 作为未来付费点。

## 7. LLM 边界与计费表

| 模块 | 确定性（免费零 LLM） | LLM（可选付费，即时扣费） |
|---|---|---|
| 九法合一 | 排盘/切片/打分/路由 | 断前尘 9 法 + 校验 + 预测 + revise/query（**现行不变**） |
| 生肖 | 犯太岁报告全量 | 无 |
| 起卦 | 卦象/课式/签文全量 | 断卦（`interpret`，注入 chart 摘要） |
| 塔罗 | 抽牌 + 牌义 + 正逆位 + 元素原型 | 牌阵综合解读（`interpret`） |
| 雷诺曼 | 抽牌 + 关键词组合解读 | 深度解读（`interpret`，复用 divination 通道） |
| 星座 | 星盘 + 行运 + 日返 + 次限 + 法达 | 本命深度解读（`interpret`） |
| MBTI | 题库 + 判型 + 16 型文案 | 无（预留 MBTI×命盘跨读） |

- 计费复用现有 `credit_transactions`（`type=consume`、`ref=tarot:{id}` / `divination:{id}` / `astrology:{id}`）。
- 扣费规则不变：`delta = -ceil(tokens/1000)`、余额可为负、下次 `check_balance` 拦截（错误码 5002）。
