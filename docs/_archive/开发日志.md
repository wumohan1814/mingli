## 2026-09-06 · 排盘引擎弹性优化（Node 常驻化 + 并发限流）

### 已完成
- [x] 新增 `backend/paipan-node/server.mjs`：Node 常驻 HTTP 服务（`127.0.0.1:9317`），启动时加载一次 iztro/mingyu-core，`POST /ziwei` 与 `POST /extra` 复用排盘逻辑（与 ziwei.cjs/extra.mjs **字节级对齐**）
- [x] `backend/app/paipan/engine.py` 改造：`run_ziwei`/`run_extra` 优先 `httpx.post` 调常驻服务，连接失败/超时/非 200/解析失败静默 fallback 到原 subprocess（降级路径原样保留）
- [x] 并发限流：`paipan()` 外层 `threading.Semaphore(paipan_max_concurrency=3)`，超出上限的调用阻塞排队
- [x] `backend/app/main.py` lifespan 拉起/回收常驻服务；`config.py` 新增 `paipan_node_url` / `paipan_node_port` / `paipan_max_concurrency`

### 决策记录
- 排盘从「每次 subprocess 开新 Node 进程」改为「常驻 HTTP 服务 + subprocess 降级」，消除多用户并发排盘时的内存峰值（N 个临时进程 → 1 个常驻进程，mingyu-core 只加载一次）
- 分层原则：lifespan 只负责拉起/回收常驻服务，engine 不感知服务是否存活，任何一层失败都自动退回 subprocess——**排盘正确性优先**
- 这是「多用户异步排盘」弹性方案的第一步（阶段 A）；后续量大了再上异步 worker 池 + 独立排盘容器水平扩展（阶段 B/C）

- 收款（小鹅通 webhook）明确排除，留待用户单独处理
