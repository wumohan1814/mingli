# 命理 H5 产品化 · 诊断与规划文档

> 文档定位：将"命理 Skill → 线上 H5 产品"的想法，从模糊设想收敛为可执行的 MVP 规划与合规框架。
> 撰写视角：产品诊断（AI 刘小排 office-hours 沉淀）+ 项目规范化补充。
> 状态：第一阶段规划稿，含 2 项待调研开放问题（见第 8 节）。
> 日期：2026-09-05

## 1. 项目背景与目标

- 现状：已有自研"命理"Skill（排盘 + 命理演算），原作为 OpenClaw 体系下的能力模块。
- 目标：将 Skill 细化为可上线的独立产品。第一阶段由 Skill 演化；第二阶段横向扩展（单手法独立化、生肖 MBTI、星座塔罗等）。
- 形态约束：
  - 不做 APP、不做微信小程序（规避平台审核与类目限制）。
  - 仅做线上 H5。
  - 不采用重型 Agent 框架（如 OpenClaw 类），使用轻量包装层。
  - 每个用户进入后拥有独立 session，自主完成算命流程。

## 2. 目标客群

### 2.1 主客群画像（第一阶段验证对象）

- 代号：王姐（化名）。
- 特征：35 岁女性职场员工，面临失业，希望通过命理获得"何时找到下一份工作"的方向感与情绪安抚。
- 痛点属性：事业运势焦虑为"现在进行时"，具备当下代价（收入中断、面子、生活压力），痛感强、频次高。
- 现状凑合方案：市面人工算命（不可靠、师傅擅长方向不一、需预约、不便）。

### 2.2 客群分野（关键判断）

- 选择 AI / 线上自助算命的用户，与找人工师傅的用户**不是同一批客群**。
- 前者偏好"自助、全套、随时可问"的产品形态；后者偏好"人"的权威感与互动。
- 推论：本产品的客群**只在"全套自助产品形态"成立时才存在**。因此 MVP 必须以产品形态本身获客；用"人工咨询链接"做验证会引入错配客群，结论无效。
- 市场已被教育：AI 算命赛道已有大量成功付费案例，付费意愿无需重新验证；待验证的是本产品的单位经济与差异化获客（见第 5、8 节）。

## 3. 产品定位与核心卖点

### 3.1 核心差异化（10x 优势）

- 多流派综合：八字 / 紫微 / 六爻等并行，单个人工师傅通常只精一种。
- 可修正：用户补充信息后结果可迭代收敛，更接近用户预期的"准"。
- 随时问：线上服务，突破预约与时空限制。
- 落地页主张应为：**"多种流派综合 + 可修正 + 随时问"**。

### 3.2 卖点表述红线

- 不主打"AI 新颖"：命理信任来自神秘感 / 权威感 / 被懂，AI 标签在命理心智中属减分项。
- 不承诺"准"：命理本质模糊，承诺"准"双向受损——用户觉不准则信任崩；监管上承诺预测具体结果近踩线。
- 采用"趋势 / 参考"话术，不输出确定结论。

### 3.3 内容定性（合规与传播）

- 对外称谓：命理文化 / 国学运势 / 事业运势分析（避免"算命"二字）。
- 禁区：不涉医疗、投资、司法预测。
- 示例改写：王姐的"什么时候找到工作" → "事业运势趋势参考"。

## 4. 合规与部署策略

### 4.1 风险归约

- 监管 / 法律风险的关键不在"服务器物理位置"，而在三要素：**收款主体、支付通道、内容定性**。服务器位置仅影响访问速度与管辖。

### 4.2 服务器部署

- 建议：香港 / 新加坡轻量节点（国内访问延迟低、免 ICP 备案、内容管辖较宽松）。
- 避免：美东等远距离节点（访问慢）。
- 与"轻量包装、不用重框架"的调性一致。

### 4.3 支付通道（最硬风险）

- 真裸奔（不推荐）：个人微信 / 支付宝收款码直收。个人码有额度天花板，"经营收款"会被要求升级商户；无主体则微信封链后零申诉通道，直接归零。
- 聪明裸奔（当前采用）：个人身份 + 借持牌内容平台（小鹅通 / 知识星球，个人可入驻，平台持支付牌照）。H5 仍自建部署，但付款按钮跳转平台链接，支付合规由平台承担，项目方仅为内容方。
- 阶段决策：个人裸奔试，小步快跑；跑出结果后转个体工商户，将资产迁入有主体护城河的壳。

### 4.4 传播风险

- 微信内分享 H5 可能被限流 / 封链接；无主体时无可申诉。
- 缓解：内容定性合规 + 不依赖单一分享通道 + 裸奔阶段不投入重内容资产（避免一封归零的沉没成本）。

## 5. 商业化框架（待最终讨论）

- 定价依据：需综合 token 费用 + 服务器费用 + 扩张费用。
- 核心变量：单位经济（单用户成本）尚未实测，定价暂不可定。
- 路径：用户已规划商业结构与商业化路径，留待最后一轮讨论。

## 6. 第一阶段 MVP 规划

### 6.1 范围

- 后端：由全 Skill 演化（用户决策，验证成本低）。
- 前端入口：需设主场景钩子（失业找工作 / 事业运势）作为默认路径；避免"什么都能算"的落地页（转化最低）。
- 第二阶段素材（感情 / 财运 / 生肖 MBTI / 塔罗）不进第一阶段前端，避免分散火力。

### 6.2 架构即成本

- 排盘、演算为确定性计算（规则引擎），应本地 / 边缘执行，**不每次调用 LLM**。
- 仅"自然语言解读 + 用户修正对话"调用模型。
- 该拆分直接决定 token 费用量级（差异可达十倍），需在架构设计阶段固化。

### 6.3 最小闭环与优先级

- 闭环：输入生辰 → 排盘 → 输出综合解读 → 支持一轮修正对话。
- 交付优先级高于获客：先自建闭环，自行跑 10 次，量出单次 token 成本，定价才有底。

## 7. 补充思考（诊断外延展）

### 7.1 留存与复购

- 算命单次低频，但事业运势因失业 / 换岗 / 晋升焦虑而反复触发，属相对高频场景。
- 需设计回访节点（月度运势、关键决策点触达），否则单位经济外的第二大商业变量（LTV）不成立。

### 7.2 数据资产

- 每用户独立 session + 生辰 + 历史对话 = 可累积的命理档案。
- 该档案是第二阶段横向扩展（生肖 MBTI / 塔罗打通）的数据底座，也是差异化护城河。
- "独立 session"不止是技术形态，是长期数据资产起点。

### 7.3 技术形态建议

- 静态 H5 + 轻函数后端（边缘函数 / Serverless），session 无状态化（token 鉴权）。
- 与"不用重 Agent 框架"一致，且利于香港节点低延迟部署。

### 7.4 获客渠道（待后续轮次）

- 客群偏好"AI 自助算命"，聚集于抖音 / 小红书"B 型"内容（非人工咨询向）及微信内。
- 获客策略留待客群与单位经济验证后细化。

## 8. 待调研开放问题（用户确认需调研后回答）

- **Q1（差异化获客）**：市面已有成功 AI 算命案例，其定价与单位经济结构如何？本产品"多流派综合 + 可修正"凭什么将用户从现有案例切过来？
- **Q2（差异化溢价）**：用户的"全套"卖点，凭什么让用户愿意比免费 / 低价案例支付更高价格？

## 9. 关键决策记录

| 项 | 决策 |
|---|---|
| 产品形态 | 线上 H5，不做 APP / 小程序 |
| 框架 | 轻量包装，不用重型 Agent 框架，独立 session |
| 第一阶段范围 | 由全 Skill 演化，前端设事业运势主钩子 |
| 部署 | 香港 / 新加坡轻节点 |
| 支付 | 个人身份 + 持牌内容平台（聪明裸奔），后续转个体户 |
| 内容定性 | 命理文化 / 事业运势趋势，不承诺结果，禁医疗 / 投资 / 司法 |
| MVP 优先级 | 先量单位经济，再定获客与定价 |
