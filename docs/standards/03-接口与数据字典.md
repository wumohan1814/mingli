# 03 · 接口与数据字典

> 契约来源：《太初技术框架方案》v2.3 §5，并与 `reference/mingli/SKILL.md` §0 / §3 / §4 对齐。
> **跨模块唯一协商点，禁止私自改字段**；Skill 升级新增字段自动惠及产品。

## 1. 对外 REST API

基路径 `/api`，鉴权 `Authorization: Bearer <访问JWT>`。除注册 / 登录外均需 JWT。

| 方法 | 路径 | 说明 | 鉴权 | 长任务 |
|---|---|---|---|---|
| POST | `/api/users/register` | 用户名 + 密码注册（无手机 / 微信）+ captcha 校验，校验 username 唯一 | 否 | — |
| POST | `/api/auth/login` | 用户名 + 密码登录，失败限流 / 锁定；错误统一 401 | 否 | — |
| POST | `/api/auth/refresh` | 刷新令牌换发新访问令牌 | 刷新令牌 | — |
| POST | `/api/cases` | 建档：生辰 / 性别 / 出生地 / 经纬度 / 真太阳时 + **主问场景**；返 `caseId` | 是 | — |
| POST | `/api/cases/{id}/paipan` | 触发排盘；返 chart 摘要 + `degradedMethods` | 是 | — |
| POST | `/api/cases/{id}/duan-qian-chen` | **异步**：9 法串行分析 + 校验；返 `202 { jobId }` | 是 | ✅ |
| POST | `/api/cases/{id}/calibration` | 提交逐条反馈；调 `score`；返权重 + 完备态 / 时辰检验 | 是 | — |
| POST | `/api/cases/{id}/predict` | **异步**：路由选法 + 并行扇出 + 合并裁决；返 `202 { jobId }` | 是 | ✅ |
| POST | `/api/cases/{id}/revise` | 多轮修正；返增量解读 | 是 | — |
| GET | `/api/cases/{id}/archive` | 命理档案查询导出（结构化 JSON，ADR-0006） | 是 | — |
| POST | `/api/cases/{id}/query/{methodKey}` | 单方法直问（bypass 主模块，缓存优先） | 是 | — |
| **GET** | **`/api/jobs/{jobId}`** | **查长任务状态**（ADR-0005）：`{ status, completed, total, result? }` | 是 | — |

### 信封

成功：`{ "code": 0, "message": "ok", "data": {…}, "meta": { "caseId": …, "stage": …, "degradedMethods": […] } }`
失败：`{ "code": <非0>, "message": "…", "detail": "…" }`

### 异步任务约定（ADR-0005）

断前尘为 **9 法串行 + 每法校验**，端到端可达数分钟，因此 `duan-qian-chen` 与 `predict` 为异步端点。

**调用流程**

```
POST /api/cases/{id}/duan-qian-chen  →  202 { jobId, total: 9 }
GET  /api/jobs/{jobId}               →  { status, completed, total, result? }
                                        status: pending | running | succeeded | failed
```

- **轮询是纯代码行为，零 LLM 调用**：`GET /api/jobs/{id}` 只读取任务进度行，不触发任何模型请求。
  LLM 仅在后端方法模块做分析 / 校验时被调用。
- 前端建议间隔 2s 起，指数退避上限 10s；终态立即停止轮询。
- 任务硬超时：断前尘 10min、预测 3min，超时标记 `failed` 并写 `error`。
- 任务失败时**已完成方法的结果仍保留**（已落 `method_results`），重试靠缓存键复用，不重复计费。
- 其余端点保持同步：`paipan` / `calibration`（纯代码）、`revise`（单轮 LLM）、
  `query/{methodKey}`（单法 + 缓存优先）、`archive`（查库）。

## 2. 事件契约（进程内分发器；Phase2 换总线，Schema 不变）

```
MethodAnalysisRequested { eventId, caseId, methodKey, phase, sliceRef, userQuestion?, calibrationFeedback? }
MethodAnalysisCompleted { eventId, caseId, methodKey, phase, methodResult, validation }
SynthesisCompleted      { caseId, report, weights }
RecordPersisted         { caseId, methodKey, record }        // 由用户档案模块发布
FeedbackReceived        { caseId, methodKey, claim, feedback, userNote }
CalibrationUpdated      { caseId, fit, weights }
```

- 幂等键：`caseId + methodKey + phase + eventId`。
- `SynthesisRequested` 已移除：主模块直接订阅 `MethodAnalysisCompleted` 合成。
- 新增 `JobProgressed`（由 `jobs` 模块订阅 `MethodAnalysisCompleted` 后推进任务进度，ADR-0005）。

**`validation` 字段（ADR-0002）**：承载校验子会话产物，仅**断前尘阶段**产出。

| 阶段 | 校验 | 说明 |
|---|---|---|
| `duan-qian-chen` | ✅ 9 法各一次，串行 | `score.py` 的「命题质量」因子（占契合度 **30%**）读取它；缺失恒取 0.5 会让权重失去区分度 |
| `prediction` | ❌ 跳过 | 改用 `confidence_level` 纪律兜底：`speculative` 不参与定论、`low` 只作参考或条件分支、冲突必须显式解释分歧来源 |

校验由独立 `validation` 模块执行（8+1 法复用），**建议使用便宜模型并单独计量**，
可整体开关（`TAICHU_VALIDATION_ENABLED`）。

## 3. 方法模块内部 I/O 契约

```
MethodInput  { method_key, phase, slice, method_prompt, calibration_feedback?,
               user_question?, guardrails{ forbidden_domains, tone, disclaimer_required } }
MethodOutput = method-result v2（原样）   // validation 另存
```

注入边界（硬）：**每法只喂自己的 slice + 自己的 method-prompt**，禁止注入其它方法的提示词或
shared 文件（mingli `SKILL.md` §0「子会话注入边界」）。

### method-result v2（复用 Skill 契约）

`{ "method": "<key>", "phase": "duan-qian-chen|prediction", "past_propositions": [ { "year_range", "domain", "claim", "confidence_level", "confidence_reason", "basis" } ] }`
预测阶段另有 `conclusions[]`，其 `direction ∈ { 吉, 凶, 平 }`。

## 4. 数据字典 · 用户分析库（MVP：`taichu_analytics`）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | `id`, `username`(UNIQUE), `password_hash`, `nickname`, `created_at`, `updated_at` | 密码用 argon2 / bcrypt，禁明文。`provider` / `external_id` 留 Phase2 |
| `refresh_tokens` | `id`, `user_id`, `token_hash`, `expires_at`, `revoked`, `created_at` | 刷新令牌服务端存储，可过期 / 清理；MVP 不暴露用户侧吊销端点 |
| `login_attempts` | `username`, `fail_count`, `locked_until` | R10 失败锁定（如 60s 内 ≥5 次失败 → 锁定 15min，阈值待实测） |
| `cases` | `id`, `user_id`, `input_json`, `current_stage`, `status`, `created_at`, `updated_at` | 鉴权为 JWT 无状态，case 不再存 `token_hash` |
| `charts` | `case_id`(PK/FK), `chart_json`, `degraded_methods`, `version`, `generated_at` | `chart.json` 全量存库，REST 按前端所需投影 |
| `method_results` | `id`, `case_id`, `user_id`, `method_key`, `phase`, `result_json`, `validation_json`, `cached`, `created_at` | 缓存命中行 `cached=true` |
| `calibrations` | `case_id`(PK/FK), `user_id`, `record_json`, `fit_json`, `updated_at` | `record_json` 为 `校准记录.json` 格式 |
| `conversations` | `id`, `case_id`, `user_id`, `turn`, `role`, `content`, `created_at` | 多轮修正增量写，不覆盖历史 |
| **`jobs`** | `id`, `case_id`, `user_id`, `type`(duan-qian-chen｜predict), `status`(pending｜running｜succeeded｜failed), `total`, `completed`, `error`, `created_at`, `updated_at` | **ADR-0005 异步任务**；进度必须落库，不得只存内存 |
| **`route_decisions`** | `id`, `case_id`, `user_id`, `phase`, `main_methods`, `support_methods`, `reasons`, `created_at` | **ADR-0004 路由决策留存**，供阶段 5 推理链路与事后复盘 |
| **`jobs`** | `id`, `case_id`, `user_id`, `type`(duan-qian-chen｜predict), `status`(pending｜running｜succeeded｜failed), `total`, `completed`, `error`, `created_at`, `updated_at` | **ADR-0005 异步任务**；进度必须落库，不得只存内存 |
| **`route_decisions`** | `id`, `case_id`, `user_id`, `phase`, `main_methods`, `support_methods`, `reasons`, `created_at` | **ADR-0004 路由决策留存**，供阶段 5 推理链路与事后复盘 |

**硬约束（多用户隔离）**：所有 `SELECT / UPDATE / DELETE` 必带 `user_id` 条件（含 `archive` 派生
视图），统一走 userId-scoped repository；JWT 提取的 `userId` 由网关注入所有模块调用。
集成测试否定用例：用户 A 持自己 token 请求用户 B 的 `caseId` 必须返 403 / 404，且日志不泄漏 B 的数据。

## 5. 数据字典 · 跨用户质疑库（MVP：`taichu_feedback`）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `feedbacks` | `id`, `case_id`, `user_id`, `method_key`, `domain`, `claim_text`, `feedback_type`(confirmed｜denied｜corrected), `user_note`, `created_at` | 用户在对话中提出的"不准 / 质疑" |
| `feedback_summaries` | `id`, `period`, `method_key`, `denied_count`, `corrected_count`, `top_issues`, `ai_analysis`, `created_at` | 后台周期聚合 → LLM 归纳 → 供方法迭代 |

## 6. 缓存键

`user_id : case_id : method_key : phase : chart_version`

- 首跑：断前尘 phase **9 法各一次 + 9 次校验**；预测 phase 主 / 辅法各一次（**0 校验**）。
- 命中：同方法再问 / 全盘再分析 / 单方法直问 → 直接返回（零 LLM 调用）。
- 失效：`chart_version` 变化（重排 / 修时辰）→ 该 user 下相关缓存失效重算。

### 首跑 LLM 调用口径（ADR-0002 / ADR-0003 修订）

| 项 | v2.3 原口径 | 现行口径 |
|---|---|---|
| 断前尘 | 8 次分析 | **9 次分析 + 9 次校验** |
| 预测（事业主问） | 主辅法数次 | **主 3（八字格局 + 大运流年 + 专题）+ 辅 2（紫微 + 七政四余）= 5 次分析，0 校验** |
| 首跑合计 | ~13 次 | **~23 次**（校验按便宜模型折算后 ≈ **15.5 次分析当量**） |

## 7. 配置项

| 键 | 取值 | 说明 |
|---|---|---|
| `TAICHU_COST_GATE_MODE` | `full` ｜ `lite` ｜ `minimal` | 成本闸门档位：`full`=完整断前尘 8 法；`lite`=方案 C（2–3 法轻量校准）；`minimal`=方案 A（仅主法 + 一轮修正）。**手动切档**，不做运行时自动切换 |
| `TAICHU_JWT_SECRET` | — | 访问令牌签名密钥 |
| `TAICHU_ACCESS_TOKEN_TTL` | 默认 1800（秒） | 访问令牌 15–30min |
| `TAICHU_REFRESH_TOKEN_TTL` | 默认 604800（秒） | 刷新令牌 7d |
| `TAICHU_DB_PATH` | — | SQLite 库文件路径（双库各一） |
| `TAICHU_AGGREGATION_WINDOW_DQC` | 默认 300（秒） | 断前尘串行聚合窗口，仅作单法卡死保护 |
| `TAICHU_AGGREGATION_WINDOW_PRED` | 默认 60（秒） | 预测并行扇出聚合窗口 |
| `TAICHU_VALIDATION_ENABLED` | 默认 `true` | ADR-0002：校验总开关；断前尘阶段生效，预测阶段本就不跑 |
| `TAICHU_VALIDATION_MODEL` | — | 校验模型名（**建议便宜模型**，与解读模型分开计量） |
| `TAICHU_JOB_TIMEOUT_DQC` | 默认 600（秒） | ADR-0005：断前尘任务硬超时 |
| `TAICHU_JOB_TIMEOUT_PRED` | 默认 180（秒） | ADR-0005：预测任务硬超时 |

> **单 case 首跑全盘成本阈值已修订**：原 ¥0.3–0.5/case 基于 ~13 次调用估算，
> 现行口径为 ~23 次（≈15.5 次分析当量），**建议上修为 ¥0.5–1.0/case**，
> 以 self-run 10× 实测校准为准（owner：用户）。
