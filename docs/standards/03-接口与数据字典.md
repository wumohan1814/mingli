## 1. 对外 REST API（C 端 `/api/*`）

基路径 `/api`，鉴权 `Authorization: Bearer <访问JWT>`（JWT HS256，ADR-0008）。
除注册 / 登录 / 图形验证码 / 免登录分享落地页类端点外均需 JWT（缺失 / 过期 → 401）。

### 1.1 认证与用户（架构 §3）

|---|---|---|---|

### 1.9 信封与异步任务约定

**信封**：成功 `{ "code": 0, "message": "ok", "data": {…} }`（少数端点附 `meta`，如 paipan 的
`meta.stage`）；失败 `{ "code": <非0>, "message": "…", "detail": "…" }`（分段见 §9）。
统一由 `main.py` 全局 exception handler 转换：`BizError` → code↔HTTP 映射；`HTTPException` →
http_to_code；`RequestValidationError` → 400/1001。

**异步任务（ADR-0005，现行）**：断前尘 / 预测为异步端点，创建 `jobs` 行 → `asyncio.create_task`
后台编排 → 立即返 `202 {jobId, total}`；前端**代码轮询** `GET /api/jobs/{jobId}`（纯读库零 LLM，
2s 起、指数退避上限 10s、终态停止；前端硬超时断前尘 10min / 预测 3min）。并发模型：**每 job 3 并发
+ 全局 100 兜底**（两层信号量嵌套，`llm_max_concurrency=3` / `llm_global_max_concurrency=100`）。

**job 幂等防重复（§7.6，现行）**：断前尘复用同 case 的 `pending/running/succeeded` job；预测复用
`pending/running` job；复用响应带 `reused:true`，杜绝刷新/重进重复跑 + 重复扣费。**断点续跑（§7.5）**：
服务重启孤儿 job 置 failed（提示重新触发）；重触发后已落库非空 MethodResult 的方法复用（cached=True，
零 LLM 零扣费），剩余方法注入 `continuation` 上下文。任务失败已完成方法结果保留，重试靠缓存复用。

**计费位置共 4 处**（排盘 / 校准打分不扣）：断前尘逐法（ref=`job:{jobId}:{methodKey}`）、预测逐法
（同上）、revise 即时（`revise:{caseId}`）、query 即时（`query:{caseId}:{methodKey}`）；外加横向扩展
即时扣费端点（§1.5/§1.6 ref 约定见 §10）。

## 2. 事件契约

### 2.1 埋点三通道（统一写 `mingli_ops.events`，架构 §11.1）

```
[前端 index.html]  --track(event, props)-->  POST /api/events（批量、防抖、异步不阻塞；可匿名带 session_id）
[FastAPI middleware] --自动记录每个 /api/* 请求--> events（api_request：method/path/status/latency_ms/user_id；
                                               跳过 /api/events 自身防递归；鉴权失败 user_id=null）
[LLM client]        --每次 chat 成功/失败-->     events（llm_call：model/prompt_tokens/completion_tokens/latency/成功失败）
```

写库失败静默（`record_event` 只记日志不抛异常，绝不阻断业务）。后台展示层中文映射见
`app/admin/router.py` 的 `EVENT_NAME_ZH`（event_key 保留英文，未收录原样返回不丢数据）。

### 2.3 进程内编排等价事件（设计契约；Phase2 升总线 Schema 不变）

模块间通信为**单进程内直接调用 + 后台任务编排**（等价事件分发，架构 §1.2），以下为设计期约定 Schema：

```
MethodAnalysisRequested { eventId, caseId, methodKey, phase, sliceRef, userQuestion?, calibrationFeedback? }
MethodAnalysisCompleted { eventId, caseId, methodKey, phase, methodResult, validation }
SynthesisCompleted      { caseId, report, weights }
RecordPersisted         { caseId, methodKey, record }        // 由用户档案模块发布
FeedbackReceived        { caseId, methodKey, claim, feedback, userNote }
CalibrationUpdated      { caseId, fit, weights }
JobProgressed           { caseId, jobId, methodKey }   // jobs 订阅 MethodAnalysisCompleted 推进进度
                                                        // （JobProgressed 载荷为设计期约定，未固化，以编排实现为准）
```

- 幂等键（Phase2 防御性预留）：`caseId + methodKey + phase`。
- `SynthesisRequested` 已移除：主模块直接订阅 `MethodAnalysisCompleted` 合成。

## 3. 方法模块内部 I/O 契约

```
MethodInput  { method_key, phase, slice, method_prompt, calibration_feedback?,
               user_question?, continuation? }
MethodOutput = method-result v2（原样）   // validation 另存 validation_json
```

注入边界（硬）：**每法只喂自己的 slice + 自己的 method-prompt**，禁止注入其它方法的提示词或
shared 文件（切片边界见架构 §5.2）。

### method-result v2（跨模块唯一协商点，禁止私自改字段）

```
{ "method": "<key>", "phase": "duan-qian-chen|prediction",
  "past_propositions": [ { "year_range", "domain", "claim",
                           "confidence_level": "high|medium|low|speculative",
                           "confidence_reason", "basis" } ],
  "conclusions": [ ... ] }        // 预测阶段；direction ∈ { 吉, 凶, 平 }
```

- `validation.json`（断前尘）**另存**于 `method_results.validation_json`，不混入 method-result；预测阶段为 null。
- `confidence_level` 归一映射（仅内部裁决用，不写回 JSON）：high≈0.8 / medium≈0.55 / low≈0.3 / speculative≈0.15。
- **校验（ADR-0002）**：仅断前尘阶段执行（9 法各一次，随该法协程）；预测阶段跳过，用 confidence_level
  纪律兜底（`speculative` 不参与定论、`low` 只作参考）。校验模型独立计量，整体开关
  `MINGLI_VALIDATION_ENABLED`。校验 tokens 并入该法差值一起扣（同一 ref）。

## 7. 缓存与复用策略（架构 §7.7，现行）

**实现口径**：以 `method_results`（`case_id + user_id + method_key + phase`）为准——已有非空
`result_json` 即命中复用（`cached=true` 标记），命中**零 LLM、零扣费**；单法直问（query）先查
prediction 缓存。

- 设计期键形（保留作约定参考）：`user_id : case_id : method_key : phase : chart_version`。
- 首跑：断前尘 phase **9 法各一次 + 9 次校验**；预测 phase 路由主 / 辅法各一次（**0 校验**）；单法再问 /
  全盘再分析 / 单法直问 → 直接返回。
- **失效边界（已知）**：现行实现**未**按 chart_version 自动失效——重排后若盘面内容变化，历史
  method_results 的语义需人工判断是否重算（`charts.version` 列已保留，供后续启用）。
- 首跑 LLM 调用口径：断前尘 9 分析 + 9 校验 + 预测主/辅法数次（随路由裁剪）；校验按便宜模型折算后
  单 case 首跑 ≈ **15.5 次分析当量**（建议成本阈值 ¥0.5–1.0/case，待实测校准）。

| 5xxx | LLM/余额 | `5001 LLM 服务不可用` `5002 余额不足` `5003 计费异常` |
| 9xxx | 系统 | `9000 内部错误` `9001 数据库错误` |

**code → HTTP 映射**（`code_to_http`）：1xxx→400；2001/2002→401；2003→403；3xxx→404；4xxx→422；
5xxx→502；其余→500。前端 `api()` 拦截统一处理，按 code 映射友好文案；9xxx/5xxx 显示「稍后重试」并上报。

## 12. 硬约束（多用户隔离）

- 所有 `SELECT / UPDATE / DELETE` 必带 `user_id` 条件（含 archive 派生视图），统一 userId-scoped
  repository；JWT 提取的 `userId` 由网关注入所有模块调用。
- 免登录端点（case_share / mbti share / assets / events / captcha / register / login）**不建会话、
  零既有数据可见**；否定用例（A 访问 B 的 caseId → 404/403 且不泄漏）列入测试。
- 档案以数据库为唯一事实源（`charts.chart_json` 全量落库，REST 投影裁剪，ADR-0006）。
