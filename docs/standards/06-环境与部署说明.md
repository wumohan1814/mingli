# 06 · 环境与部署说明

> 环境划分与部署步骤的**待补清单**。目录骨架阶段只固化结构与责任边界，命令细节随首个模块落地补充。

## 1. 环境划分

| 环境 | 用途 | 数据库 | 部署位置 |
|---|---|---|---|
| `local` | 开发自测、self-run 10× 成本实测 | 本地 SQLite 文件 | 开发机 |
| `staging` | 预发验证（含合规护栏回归） | 独立 SQLite 实例 | 轻量云节点 |
| `production` | 线上 H5 | 独立实例（Phase2 起 PostgreSQL） | 香港 / 新加坡轻量云 + CDN |

## 2. 部署拓扑（MVP）

```
[浏览器] ──HTTPS──▶ [静态 H5 / CDN]
                       │ REST/JSON (Bearer JWT)
                       ▼
        单一容器（模块化单体）
        ├─ FastAPI 网关：鉴权 / 限流 / captcha / CORS
        ├─ 方法模块 ×8（并列）
        ├─ 排盘基础模块（Python 调 Node 子进程）
        ├─ 主模块（跨方法合成器）
        ├─ 用户档案模块 / 质疑模块 / 合规护栏（横切）
        └─ 进程内事件分发器
                       │
                       ▼
        mingli_analytics（用户分析库） + mingli_feedback（跨用户质疑库）
```

- MVP **单进程单实例**；JWT 无状态是为 Phase2 水平扩展预留，MVP 不做多实例。
- 容器镜像必须同时包含 **Python 3.13 与 Node 22**（排盘引擎硬约束）。

## 3. 环境变量

以 `ops/env/.env.example` 为唯一来源，新增变量须同步：
`ops/env/.env.example` → 本表 → `docs/standards/03-接口与数据字典.md` §7。

| 变量 | 必填 | 环境 | 说明 |
|---|---|---|---|
| `MINGLI_ENV` | 是 | 全部 | `local` ｜ `staging` ｜ `production` |
| `MINGLI_DB_PATH` | 是 | 全部 | 用户分析库路径 |
| `MINGLI_FEEDBACK_DB_PATH` | 是 | 全部 | 跨用户质疑库路径 |
| `MINGLI_JWT_SECRET` | 是 | staging / production | 访问令牌签名密钥（**HS256，ADR-0008**）：随机生成 ≥32 字节，各环境不同值，走平台密钥管理不落文件；泄露即全量失效 |
| `MINGLI_ACCESS_TOKEN_TTL` | 否 | 全部 | 默认 1800 秒 |
| `MINGLI_REFRESH_TOKEN_TTL` | 否 | 全部 | 默认 604800 秒 |
| `MINGLI_LLM_API_KEY` | 是 | 全部 | 解读模型凭据 |
| `MINGLI_LLM_MODEL` | 是 | 全部 | 解读模型名（成本计量锚点） |
| `MINGLI_COST_GATE_MODE` | 否 | 全部 | 默认 `full`，self-run 后手动切档 |
| `MINGLI_CAPTCHA_*` | 否 | staging / production | captcha 供应商凭据（选型待定；**建议仅异常频次触发**，降注册摩擦） |
| `MINGLI_NODE_BIN` | 否 | 全部 | Node 可执行文件路径，缺省走 `PATH` |
| `MINGLI_VALIDATION_ENABLED` | 否 | 全部 | 默认 `true`：断前尘校验总开关（ADR-0002） |
| `MINGLI_ALLOW_PUBLIC_REGISTER` | 否 | 全部 | **默认 `false`（节141）**：公开注册总开关。false 时 `POST /api/auth/register` 一律 403（内测白名单制，新账号只由后台「新增 C 端用户」创建）；仅测试造数时置 `true` |
| `MINGLI_SITE_DOMAIN` | 是（Docker 部署） | staging / production | **站点域名（节147：可配置项）**。`docker-compose.yml` 透传给 caddy 容器，`Caddyfile` 用 `{$MINGLI_SITE_DOMAIN}` 取它申请 Let's Encrypt 证书。**未配置时 Caddy 启动失败**（有意为之：不让占位域名去申请证书）。⚠️ **仓库里一律写占位（`mingli.example.com`）；真实域名只写在未入库的 `.env`** —— 否则一开源就暴露 |
| `MINGLI_CADDY_EXTRA` | 否 | staging / production | **可选附加站点文件（节147）**：默认不设 = 挂载仓库里的 `ops/deploy/caddy-extra.empty`（空文件，等于不启用）。要启用（如自建 Agent 接入点）就设成 `./ops/deploy/caddy-extra.caddy`；**该文件已被 `.gitignore` 排除**，填进去的真实域名/内网地址不会进仓库 |
| `MINGLI_VALIDATION_MODEL` | 否 | 全部 | 校验模型名，建议便宜模型，与解读模型分开计量 |
| `MINGLI_JOB_TIMEOUT_DQC` | 否 | 全部 | 默认 600 秒：断前尘任务硬超时（ADR-0005） |
| `MINGLI_JOB_TIMEOUT_PRED` | 否 | 全部 | 默认 180 秒：预测任务硬超时（ADR-0005） |
| `MINGLI_OPERATOR_NAME` / `MINGLI_OPERATOR_CONTACT` / `MINGLI_OPERATOR_EMAIL` | 是（线上） | staging / production | **合规文书运营主体（节147 续）**。用户协议 / 隐私政策是**线上要展示**的合规文书，必须写真实主体；但项目要开源 → 仓库里两份文书只放 `{{OPERATOR_NAME}}` / `{{OPERATOR_CONTACT}}` / `{{OPERATOR_EMAIL}}` 占位符，由后端服务端渲染注入（`app/legal.py`）。⚠️ **三项任一为空时 `/legal/*.html` 返回 500**（宁可 500，也不发布没有运营主体的协议）；本地开发可留空，启动会打 warning |

## 4. 本地启动（待补）

## 7. 胖 APK 构建环境与出包

> APK 链路与 Web 部署**相互独立**：两者各自更新、各自发版，**不做双端自动同步**（见 `docs/standards/08-运行形态与版本契约.md`）。
> 本节只记「工具链怎么装、怎么在本机出包、CI 怎么跑」。

### 7.1 本机工具链（`C:\AndroidDev`）

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | Temurin **21.0.12.1+1** | `JAVA_HOME=C:\AndroidDev\jdk` |
| Android cmdline-tools | **23.0.0**（rev 23） | 提供 `sdkmanager`；⚠️ rev 23 起 `--licenses` 变 no-op（licenses 目录自动生成），且该工具打印完列表后可能崩 `0xC0000409`，**核验一律以磁盘产物 + `--list_installed` 为准，别信退出码** |
| build-tools | **36.0.0** | `aapt2` / `apksigner` / `d8` / `zipalign` |
| platforms | **android-36**（rev 2.0.0） | `android.jar` |
| platform-tools | **37.0.1** | `adb`（真机安装用；构建本身不需要） |
| Gradle | **8.14.3** | `C:\AndroidDev\gradle\gradle-8.14.3` |

- **环境用 dot-source 生效**：每条命令前先 `. C:\AndroidDev\env.ps1`。**刻意不用 `setx`** —— 短命进程继承不到新注册表值，
  而 `env.ps1` 会把 `JAVA_HOME` / `ANDROID_HOME`（= `ANDROID_SDK_ROOT`）/ `GRADLE_HOME`（自动探测 `gradle\gradle-*`，
  版本升级不必改脚本）/ `PATH`（前置四项）一次性设好。
- 后续要装 NDK / Rust（APK 后段前置，见技术栈清单 T11 / T14）：
  `sdkmanager --sdk_root=C:\AndroidDev\sdk "ndk;28.2.13676358"`；Rust 装 rustup 后
  `rustup target add aarch64-linux-android`。

### 7.2 本机网络现实（实测，装链前必须先知道）

| 现象 | 实测结论 |
|---|---|
| `github.com` HTTPS | **不可达**（`objects.githubusercontent.com` / `codeload` / `raw` 均超时）；但 **SSH(22) 与 `api.github.com` 可用** → `git push` 正常，**极易误判"网络没问题"** |
| Adoptium / services.gradle.org 下载 | **302 跳 GitHub releases** → 会**卡死**（实测 `jdk21.zip` 卡在 18 MB、`gradle.zip` 卡在 7.4 MB 后零增长） |
| 可用镜像与吞吐（实测） | 清华 Adoptium **31.6 MB/s** · 腾讯云 Gradle **28.3 MB/s** · 华为云 OpenJDK 10.2 MB/s · `dl.google.com`（SDK 组件）仅 **491 KB/s**（可用但慢） · `mirrors.cloud.tencent.com/AndroidSDK/` 可作 SDK 备选 |
| 换源判据 | **停滞 = 20 秒内字节数不增长 → 立即 kill 换源**，不要挂着等 |

### 7.3 Gradle 仓库策略

- `apk/settings.gradle.kts` **默认国内镜像优先**（阿里云 `google` / `public` / `gradle-plugin`），官方源排在后面兜底
  （实测 google 仓库 **6.16 MB/s** vs 官方 `dl.google.com` 0.86 MB/s）。
- 境外构建（如 CI）显式关闭：`gradle assembleDebug -PmingliApkUseChinaMirrors=false`。
- 注意：`plugins.gradle.org` 走 Cloudflare，本机曾出现**只建连接不下载**（构建卡在配置期十余分钟、缓存零增长）。

### 7.4 本机出包（三步）

```powershell
. C:\AndroidDev\env.ps1                      # 1. 装环境（每次新开终端都要）
cd apk
powershell -File tools\sync-assets.ps1       # 2. 同步生成物（CI/Linux 用 bash tools/sync-assets.sh）
gradle assembleDebug                         # 3. 出包
```

- 产物：`apk/app/build/outputs/apk/debug/app-debug.apk`（约 **51 MB**，**debug 签名，可直接安装**）。
- **生成物一律不入库**（规则在 `apk/.gitignore`）：`app/src/main/python/`、`app/src/main/assets/web/`、
  `app/src/main/assets/paipan/`、`build/`、`*.log`。故**首次构建前必须先跑同步脚本**，否则包内缺文件。
- 同步脚本两条硬约束（改动前先读 `apk/README.md` 与脚本文件头）：① 后端必须保留 `python/app/` 与
  `python/prompts/` 两级（绝对包导入与 `parents[2]/"prompts"` 依赖它）② `apk/pysrc` 的自举服务**平铺在 python 根**
  （MainActivity 按顶层模块名取）。⚠️ 改 `.ps1` 后**必须复核文件头 UTF-8 BOM 仍在**（PowerShell 5.1 会把无 BOM 的脚本按 CP936 解码，报出像语法错的乱码错误）。

### 7.5 CI 出包

- 工作流 `.github/workflows/apk.yml`（名 `apk-poc0`）：`ubuntu-latest` + JDK 21 + Python 3.13 +
  `gradle/actions/setup-gradle@v4`（钉 8.14.3）+ `bash apk/tools/sync-assets.sh` +
  `gradle assembleDebug -PmingliApkUseChinaMirrors=false` + 上传 artifact **`mingli-apk-poc0-debug`**（保留 14 天）。
- 触发条件：`workflow_dispatch`，或 push 改到 `apk/**` 或该工作流文件。
- **首次云端运行已成功**（APK 可从该次运行的 artifact 下载）。

### 7.6 APK 出包检查清单

- [ ] 同步脚本跑过且退出码 0（打印件数：pysrc / app / prompts / web），`python/app` 与 `python/prompts` 层级正确
- [ ] `gradle assembleDebug` 为 `BUILD SUCCESSFUL`（单 ABI 时确认 ABI 与目标手机一致：只支持 64 位）
- [ ] 产物元数据核对：`com.mingli.apk`、versionCode/versionName、minSdk 24 / targetSdk 36、仅 `INTERNET` 权限
- [ ] 签名校验通过（debug 证书可直接装；**release 需另配签名**，当前未做）
