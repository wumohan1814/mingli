# 04 · 环境与部署说明

> 环境划分与部署步骤的**待补清单**。目录骨架阶段只固化结构与责任边界，命令细节随首个模块落地补充。

## 1. 环境划分

| 环境 | 用途 | 数据库 | 部署位置 |
|---|---|---|---|
| `local` | 开发自测、self-run 10× 成本实测 | 本地 SQLite 文件 | 开发机 |
| `staging` | 预发验证（含合规护栏回归） | 独立 SQLite 实例 | 轻量云节点 |
| `production` | 线上 H5 | 独立实例（Phase2 起 PostgreSQL） | 香港 / 新加坡轻量云 + CDN |

## 2. 部署拓扑（MVP）

```
[浏览器] ──HTTPS──▶ [静态 H5 / CDN]
                       │ REST/JSON (Bearer JWT)
                       ▼
        单一容器（模块化单体）
        ├─ FastAPI 网关：鉴权 / 限流 / captcha / CORS
        ├─ 方法模块 ×8（并列）
        ├─ 排盘基础模块（Python 调 Node 子进程）
        ├─ 主模块（跨方法合成器）
        ├─ 用户档案模块 / 质疑模块 / 合规护栏（横切）
        └─ 进程内事件分发器
                       │
                       ▼
        mingli_analytics（用户分析库） + mingli_feedback（跨用户质疑库）
```

- MVP **单进程单实例**；JWT 无状态是为 Phase2 水平扩展预留，MVP 不做多实例。
- 容器镜像必须同时包含 **Python 3.13 与 Node 22**（排盘引擎硬约束）。

## 3. 环境变量

以 `ops/env/.env.example` 为唯一来源，新增变量须同步：
`ops/env/.env.example` → 本表 → `docs/standards/03-接口与数据字典.md` §7。

| 变量 | 必填 | 环境 | 说明 |
|---|---|---|---|
| `MINGLI_ENV` | 是 | 全部 | `local` ｜ `staging` ｜ `production` |
| `MINGLI_DB_PATH` | 是 | 全部 | 用户分析库路径 |
| `MINGLI_FEEDBACK_DB_PATH` | 是 | 全部 | 跨用户质疑库路径 |
| `MINGLI_JWT_SECRET` | 是 | staging / production | 访问令牌签名密钥（**HS256，ADR-0008**）：随机生成 ≥32 字节，各环境不同值，走平台密钥管理不落文件；泄露即全量失效 |
| `MINGLI_ACCESS_TOKEN_TTL` | 否 | 全部 | 默认 1800 秒 |
| `MINGLI_REFRESH_TOKEN_TTL` | 否 | 全部 | 默认 604800 秒 |
| `MINGLI_LLM_API_KEY` | 是 | 全部 | 解读模型凭据 |
| `MINGLI_LLM_MODEL` | 是 | 全部 | 解读模型名（成本计量锚点） |
| `MINGLI_COST_GATE_MODE` | 否 | 全部 | 默认 `full`，self-run 后手动切档 |
| `MINGLI_CAPTCHA_*` | 否 | staging / production | captcha 供应商凭据（选型待定；**建议仅异常频次触发**，降注册摩擦） |
| `MINGLI_NODE_BIN` | 否 | 全部 | Node 可执行文件路径，缺省走 `PATH` |
| `MINGLI_VALIDATION_ENABLED` | 否 | 全部 | 默认 `true`：断前尘校验总开关（ADR-0002） |
| `MINGLI_ALLOW_PUBLIC_REGISTER` | 否 | 全部 | **默认 `false`（节141）**：公开注册总开关。false 时 `POST /api/auth/register` 一律 403（内测白名单制，新账号只由后台「新增 C 端用户」创建）；仅测试造数时置 `true` |
| `MINGLI_VALIDATION_MODEL` | 否 | 全部 | 校验模型名，建议便宜模型，与解读模型分开计量 |
| `MINGLI_JOB_TIMEOUT_DQC` | 否 | 全部 | 默认 600 秒：断前尘任务硬超时（ADR-0005） |
| `MINGLI_JOB_TIMEOUT_PRED` | 否 | 全部 | 默认 180 秒：预测任务硬超时（ADR-0005） |

## 4. 本地启动（待补）

1. 准备 Python 3.13 与 Node 22 双运行时。
2. 安装后端依赖（`backend/` 下 requirements 待生成）。
3. 安装排盘引擎依赖：`lunar-python`（Python）+ `iztro` / `mingyu-core`（Node，国内源用 npmmirror）。
   **排盘胶水 / 切片 / 打分 / 提示词为自研**（ADR-0001），`backend/reference/mingli-reference/` 不参与构建。
4. 初始化双库：执行 `data/migrations/` 下迁移（工具待定，见技术栈清单 T1）。
5. 复制 `ops/env/.env.example` 为 `.env` 并填写。
6. 启动后端（Uvicorn）与前端（Vite）。

## 5. 数据库初始化与迁移

- Schema 以 `data/schema/` 下的 DDL 为准，迁移脚本置于 `data/migrations/`，**两库各自独立版本线**。
- 破坏性变更必须提供回滚脚本，并在 `docs/standards/05-版本迭代记录.md` 标注。
- SQLite → PostgreSQL 切换时点见技术栈清单 T7。
