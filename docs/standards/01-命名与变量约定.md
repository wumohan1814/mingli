# 01 · 命名与变量约定

> 目标：跨前端 / 后端 / 数据库 / 提示词的**同一个概念只有一个名字**。

## 1. 目录与文件

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录 | 小写 + 连字符 | `method-prompts/`、`runbooks/` |
| 规范文档 | 两位数字前缀 + 中文短名 | `03-接口与数据字典.md` |
| 资产文件 | 小写 + 连字符 | `chart-empty-state.svg` |
| 说明文件 | 目录内 `README.md`（纯资产目录另加 `.gitkeep`） | `backend/app/methods/README.md` |

## 2. Python（后端）

| 对象 | 规则 | 示例 |
|---|---|---|
| 包 / 模块 / 函数 / 变量 | `snake_case` | `paipan_service.py`、`build_questionnaire()` |
| 类 | `PascalCase` | `MethodResult`、`CaseRepository` |
| 常量 | `UPPER_SNAKE_CASE` | `DEFAULT_AGGREGATION_WINDOW` |
| 内部使用 | 单下划线前缀 | `_load_prompt()` |
| 测试 | `test_<行为>_<预期>` | `test_cross_user_read_returns_403` |

## 3. TypeScript（前端）

| 对象 | 规则 | 示例 |
|---|---|---|
| 组件与组件文件 | `PascalCase` | `ChartBoard.tsx` |
| Hook | `use` 前缀 + `PascalCase` | `useCasePolling.ts` |
| 变量 / 函数 | `camelCase` | `fetchQuestionnaire` |
| 类型 / 接口 | `PascalCase`，不加 `I` 前缀 | `MethodResult`、`CaseDetail` |
| 常量 | `UPPER_SNAKE_CASE` | `POLLING_INTERVAL_MS` |
| 服务 / 状态 | 后缀 `Service` / `Store` | `caseService.ts`、`authStore.ts` |

## 4. 数据库（SQLite → PostgreSQL）

| 对象 | 规则 | 示例 |
|---|---|---|
| 库 | 小写 + 下划线 | `taichu_analytics`、`taichu_feedback` |
| 表 | `snake_case` 复数 | `cases`、`method_results`、`refresh_tokens` |
| 字段 | `snake_case` | `user_id`、`created_at`、`degraded_methods` |
| 主键 | `id` | `cases.id` |
| 外键 | `<实体单数>_id` | `case_id`、`user_id` |
| 时间 | `created_at` / `updated_at` / `expires_at` | — |
| 布尔 | `is_` / `has_` 前缀（存量 `revoked` 例外） | `is_degraded` |
| 索引 | `idx_<表>_<字段>` | `idx_method_results_cache_key` |

## 5. REST 接口

| 对象 | 规则 | 示例 |
|---|---|---|
| 路径 | `/api/<资源复数>[/<id>][/<动作>]`，全小写 + 连字符 | `/api/cases/{id}/duan-qian-chen` |
| 资源标识 | 路径参数用 `{id}` 语义名 | `{caseId}`、`{methodKey}` |
| JSON 字段 | `camelCase` | `caseId`、`degradedMethods`、`methodKey` |
| 触发型动作 | `POST` + 动词短语路径 | `POST /api/cases/{id}/predict` |
| 查询型 | `GET` + 资源路径 | `GET /api/cases/{id}/archive` |

> 数据库与内部事件用 `snake_case`，对外 REST JSON 用 `camelCase`。边界层做一次显式转换，禁止混写。

## 10. 领域术语（禁止混用的易错词）

## 12. 文案 key 规范（UI 文案 / 正文内容）

> 全站文案统一 key 化（免构建单文件内的集中常量表 + 数据文件），试点见 REQ-128 阶段 0
>（6 套名词白话卡接入 + 数据文件 `frontend/public/data/term-cards.js`）。

| 类别 | key 规则 | 示例 |
|---|---|---|
| 界面字（按钮 / 提示 / 错误 / 状态） | `ui.<模块>.<动作\|状态>` | `ui.button.start`、`ui.tip.loading`、`ui.error.network` |
| 正文类 / 内容（词条 / 术语 / 解读正文） | `content.<模块>.<条目>` | `content.liuren.tianshen`；名词卡 key 已按此风格：条目部分如 `tianjiang-guiren`（天将·贵人）、`quzhuan-yuanzong`（九宗门·元首），方法维度即所在卡组（`liuren` / `jinkoujue` / `qimen` / `almanac` / `taiyi` / `huangji`） |

- 命名一律**小写字母 + 连字符**；模块名与现有方法 key / 页面 id 对齐（如 `liuren`、`jinkoujue`、`qimen`、`almanac`、`taiyi`、`huangji`、`liuyao`）。
- 新功能文案**必须**进本规范，并在开发验收项中加入「**新功能验收含文案 key 合规检查**」。
- 文案正文为交付物：接入方只做搬运与 UI 接线，不擅自改写正文；正文轮次更新只替换对应数据 / 常量文件（名词白话卡即只替换 `frontend/public/data/term-cards.js`）。
- **物理归口（文件放哪、怎么引用）本节不重复，唯一权威在 `00_根/复用.md` §四**：界面词 → `frontend/public/data/ui-copy.js`（`TC_COPY.ui`，别名 `UI_COPY`）；正文 → `frontend/public/data/content/<领域>/`（`CONTENT`）；视觉令牌 → `frontend/public/css/tokens.css`；美术素材文件 → `frontend/public/art/<用途子目录>/`（引用三分法见该表「图标 / 美术素材」行）。破竹合规自检第 5/6 项（文案集中 / UI 元素统一处）以此四处为检查对象。
