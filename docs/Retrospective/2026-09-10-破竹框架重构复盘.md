## 可复用结论（现象 → 根因 → 规则 → 落地检查项）

1. **现象**：pwsh 命令行整批写中文文件，7/10 个文件内容损坏（README 混入后续条目源码、`resp` 字符被吞、反引号丢失；3 个文件完全没写出来）。
   **根因**：shell 命令通道对中文 / 特殊字符（↔、`"@`、反引号）的编码不可靠，here-string 终止符解析错位。
   **规则**：中文 / UTF-8 文件**只用受控编辑工具（edit / write）或显式 UTF-8 编码写入，禁止 shell 整文件覆写**；批量写后逐文件 read 抽查首尾与特殊字符。
   **落地检查项**：任何中文文件写入后，抽查 1–2 个含特殊字符的行；批量操作看文件数与预期一致。

2. **现象**：原 AGENTS.md 红线引用 `standards/05-版本迭代记录.md`，实际是 `07`（05 = 前端组件库规范）。
   **根因**：规范文件编号变更未同步更新引用点。
   **规则**：引用规范 / 文件路径前，先 grep 实际文件名核对；新文件名入文要带"以磁盘为准"的核验习惯。
   **落地检查项**：引用任何路径后 `Test-Path` 或 grep 一次。

3. **现象**：`git mv` 后做 `git reset` 再按新路径 `git add`，导致重命名的**删除侧**漏暂存（提交只含新增，旧路径残留未暂存 D）。
   **根因**：reset 解除暂存后，重命名退化为"删除 + 新增"两个独立变更，只 add 新路径会漏删除侧。
   **规则**：移动文件后核验 `git diff --cached --stat` 出现 `R`（重命名）条目；发现只有新增时用 `git add -u <旧路径>` 补删除侧再 `--amend`。
   **落地检查项**：任何 git mv 提交前，确认 staged 里是 R 而非孤立的 A + D。

4. **现象**：`frontend/public/index.html` 21841 行，实测超出自设红线「2 万行必须拆」。
   **根因**：单文件前端架构（FE-001）长期累积，未在超限时触发拆分决策。
   **规则**：自设红线要有"超限即登记"的执行机制（登记 40_节/待办 + 入口下一步，不静默忍）；大件先规划拆分再动手。
   **落地检查项**：每节收尾对照 00_根/复用.md 红线自查一次。

5. **现象**：跨工作区（兄弟目录 `Ratoon-破竹/库/`）写入被沙箱 workspace-write 拒绝。
   **根因**：沙箱只覆盖当前工作区；资产库在工作区之外。
   **规则**：先正常尝试 → 真实拒绝后一次性提权（danger-full-access）+ 用户批准，不绕过、不反复试。
   **落地检查项**：写工作区外文件前先确认用户意图；被拒后只提权一次。
