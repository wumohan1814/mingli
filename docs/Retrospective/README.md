# Retrospective · 跨项目可复用工程资产包

> 本目录是从上一个项目全程复盘（源材料见 `原始复盘/`）中提炼、剥离业务细节后的**工程协作资产**，
> 用于启动下一个完全不相关的项目时直接复用。
>
> 提炼原则：**保留"怎么工作 / 怎么协作 / 怎么留痕"的工程经验，剥离一切业务实体**
> （产品功能、领域模型、具体第三方库、具体接口一律以占位符表示）。
>
> 资产版本：**v5** —— 新增 `01` §4「Agent 运行成本准则（Token 经济）」与 `02` §1.8「运行成本与上下文纪律」（会话收敛 / 大文件纪律 / 通道选择 / 失败诊断 / 并行按需 / 账本计量）；v4 吸收 2026-09-06~09-10 全部复盘与代码知识库实践；Agent Prompt 三合一为单文件 AGENTS（`02-AGENTS-统一`），旧三份分离版归档于 `原始复盘/`；新增 Code-Wiki 范式（`03`）作为文档体系**常驻参考层**。

## 占位符约定

| 占位符 | 含义 | 套用时替换为 |
|---|---|---|
| `{{项目名}}` | 项目名称 | 新项目名 |
| `<模块>` / `<模块名>` | 业务模块 | 实际模块名 |
| `<REQ-xxx>` / `<BUG-yyy>` | 需求 / Bug 编号 | 沿用此编号规范（全局递增三位序号） |
| `<测试命令>` / `<验证命令>` | 项目特定的验证手段 | 实际命令 |
| `<网络前提>` / `<批准人>` / `<主分支>` | 环境 / 流程相关前提 | 实际约定 |

## 怎么套用到新项目

1. **首个 Agent 建项**：把本包全部文档 + `08-启动检查清单.md` 交给首个 Agent，让它按清单**逐条向你提问确认**，一边确认一边建立项目骨架（文档体系 / 协作协议 / 角色边界 / 工程基线）。
2. 通读 `01-项目准则.md`，把它作为新项目的**最高工程准则**（冲突优先级：用户口头指令 > 本准则 > 项目文档）。
3. **单文件 AGENTS**：把 `02-AGENTS-统一（三角色合一）.md` 拷贝为新项目仓库根 `AGENTS.md`——运行时只读一份；**公共部分三个团队都遵守，三个角色块（开发 / 测试组 / 需求与Bug管理）按当前 session 任务自适配**。文档内置**"定期复盘"要求**：每个里程碑 / 阶段结束后，沉淀"背景、问题/方案、适用场景、可复用结论"四段式、与业务无关的抽象复盘到 Retrospective 目录。
4. 若首个 Agent 尚未建好：按 `06-文档范式-协作守则.md` 建立协作协议，按 `07-文档模板-需求与Bug.md` 建立需求表与 Bug 表，按 `05-文档范式-交接文档.md` 建立交接文档，按 `03-文档范式-Code-Wiki（代码知识库）.md` 建立 Code-Wiki 骨架（常驻代码地图，代码落地后持续更新）。
5. 把 AGENTS 中指向"本文档 / 协作协议 / 需求表 / Bug 表 / 交接文档"的引用，替换为新项目实际文件路径。

## 状态机与角色权责速查（贯穿全包的约定）

| 状态 | 含义 | 谁设置 | 下一个动作 |
|---|---|---|---|
| 🟡 待办 | 已登记，未开始 | 登记方 | 责任人认领 → 🔵 |
| 🔵 进行中 | 正在处理 | 处理方 | 完成 → 🟠（备注"待验收 / 待验证"） |
| 🟠 待验收 / 待验证 | 处理完成，等验收 | 处理方 | 验收方 → 🟢 / 退回 🔵 |
| 🟢 已验收 / 已修复 | 验收通过 | **仅测试组（验收方）** | 结束 |
| ⚪ 已归档 / 已关闭 | 明确不做 / 不复现 / 重复 | 登记方（注明原因） | — |

> **铁律**：🟢 只能由**测试组（验收方）**设置；开发方最多置 🟠。
> 状态变更必须连同**退回细则 / 细化口径**一起写进备注——备注就是下一批任务的 spec。
