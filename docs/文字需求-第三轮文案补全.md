## 二、交付格式要求

- 每个编号一个 JSON 文件（或按 module 拆），放入 `docs/文案交付-第三轮/`，并附 `交付说明.md` 说明入库位置与字段结构。
- 中文 UTF-8、`ensure_ascii=False`；软性措辞；注明来源（A 类）/ 原创（B 类）。

### 2.1 匹配对统一 JSON 结构（T1–T4）

```json
{
  "module": "zodiac_love",
  "dim": "12x11",
  "score_scale": "1..5",
  "score_note": "5 星制，整数或 .5 半星；分值需据星座/生肖性格通识有理据，分布自然、勿全中位数",
  "pairs": [
    { "self": "白羊座", "other": "金牛座", "score": 4, "text": "……（60–120 字，软性说明）……" }
  ]
}
```

- **module 取值**：T1=`zodiac_love`；T2=`zodiac_friend`；T3=`zodiac_boss`；T4 拆三文件 `shengxiao_love` / `shengxiao_friend` / `shengxiao_boss`。
- **星座维度（T1–T3）**：`self`/`other` 取值「白羊座…双鱼座」共 12；`self`=当前档案侧，`other`=其余 11；单向 132 条。
- **生肖维度（T4）**：`self`/`other` 取值「鼠牛虎兔龙蛇马羊猴鸡狗猪」共 12；含恋爱/朋友/上下级三套，共 396 条。
- **对称性**：分值对称（A×B 与 B×A 同分）；文案按「self 视角 → other」单向各写一条；A×B 与 B×A 文案可复用改写，但视角须翻转（「你是白羊、对方金牛」vs「你是金牛、对方白羊」）。

### 2.2 说明文字（text）口径

- 每条 60–120 字，写「双方契合点 / 相处宜注意 / 可关注方向」，**不写宿命或成败断言**。
- 用「倾向 / 宜 / 可关注 / 可留意」软性措辞，禁「一定 / 注定 / 必然 / 绝对」；尾部可缀「仅供趋势参考」。
- 星座维度可参考星座性格通识多源改写；生肖维度参考生肖性情通识，与星座维度**文字体系区分**（措辞、切入点各自独立，不复用同一套模板句）。

### 2.3 T5 / T6

- **T5**：交付候选文案数组（主按钮短文案 ≤6 字 + 可选一句 hover 说明），标注「占位」；收到品牌文案后替换并随文案轮次校订。
- **T6**：交付「未替换硬编码按钮文案清单 + 建议替换文案」对照表（基于 C5 已定稿 `UI_COPY`），供开发逐处落地。

### 2.4 版权与合规

- T1–T4 均为 **B 原创 / 多源改写**，不得逐字复制单一商业付费文案源。
- 全站保留 `disclaimer_full` / `footer_note`；趋势类文案统一软性措辞。
