# 太初 · 需求表（Requirement Tracker）

> 本表是项目需求的**单一事实源**：新需求在此登记、分配 ID、追踪状态；开发按表推进，完成后更新状态。
> 每次会话涉及的新需求 / 状态变更，收尾前同步回本表。

## 使用说明

1. **登记**：新需求在对应模块新增一行，分配 `REQ-<三位序号>`（全局递增）。
2. **查重合并**：登记前先与全表比对——与已有条目重复 / 高度相似者**不新增行**，并入已有条目（保留原 ID，合并补充描述，备注注明「并入于 <日期>：<新增点>」）；部分重叠者拆并入最贴近条目或在备注交叉引用，避免同一需求多行、状态分叉。
3. **状态**：🟡 待办 · 🔵 进行中 · 🟠 待验收（开发完成等测试）· 🟢 已验收 · ⚪ 已归档（明确不做）。
4. **优先级**：P0 阻塞 / P1 高 / P2 中 / P3 低。
5. **粒度**：一条需求对应一个可验收的用户可感知功能或明确的工程改造，不混多件事。
6. 状态流转：🟡 → 🔵 → 🟠 → 🟢（或 ⚪）。🟢 只能由测试组验收通过后设置；开发完成置 🟠 并在备注写「待验收」。
7. **可执行性保证**：本表发出的需求必须做到「开发可直接照做」——含明确动作主体与范围 + 可验收口径（期望行为 / 通过标准）；描述含糊（如「优化体验」「尽快」）、缺验收口径或多义时，**先向需求方确认补齐后再登记**，不得凭推测落表。
