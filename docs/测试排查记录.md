## 二、排查方法（接手必读）

### 1. 看后端日志（uvicorn 窗口）
- 每条请求一行：`INFO: 127.0.0.1 - "POST /api/xxx HTTP/1.1" 200 OK`。**状态码是关键**：401=未登录、404=不存在/越权、422=参数错、500=后端异常、502=LLM 服务不可用。
- LLM 每次调用成功会打：`LLM chat 成功 model=... prompt_tokens=... completion_tokens=... total_tokens=...`。
- 编排器任务完成会打：`断前尘任务完成 job_id=... method_count=... failed=... total_tokens=...`（预测同理）。

### 2. 查数据库里的 token 用量（self-run 成本）
```bash
cd backend
python -c "
from app.database import AnalyticsSession
from app.models import Job
s = AnalyticsSession()
for j in s.query(Job).order_by(Job.id).all():
    u = (j.result_json or {}).get('_usage') if isinstance(j.result_json, dict) else None
    print(f'job={j.id} type={j.type.value if j.type else None} status={j.status.value if j.status else None} usage={u}')
s.close()
"
```
- `result_json._usage` = `{prompt_tokens, completion_tokens, total_tokens, calls}`（该任务合计）。
- 单 case 首跑全盘成本 = 断前尘 job 的 usage + 预测 job 的 usage。

### 3. 前端排查
- 浏览器 F12 → Console 看报错；Network 看请求状态码与响应体。
- 前端错误信息现在会显示**可读的 detail**（不再是 `[object Object]`）。

## 三、self-run 记录（成本实测）

### DeepSeek-V4-Flash 官方定价（2026-08-17 起，元 / 百万 tokens）

| 时段 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
|---|---|---|---|
| 空闲 | 0.05 | 1.5 | 4.5 |
| 高峰 | 0.10 | 3.0 | 9.0 |

- **高峰时段（北京时间，工作日）**：9:00–12:00、14:00–18:00；其余为空闲；周末/节假日全空闲。
- **计费字段**（DeepSeek usage）：`prompt_cache_hit_tokens`=缓存命中输入、`prompt_tokens`=未命中输入、`completion_tokens`=输出，分开扣费。
- 并发上限 2500。

### 成本计算方法

```bash
cd backend && python scripts/cost.py
```
脚本从 `jobs` 表读每个任务的 `result_json._usage`（已含 `prompt_cache_hit_tokens`），按任务完成时刻的北京时间判断峰谷，套单价算金额。

| 轮次 | 日期 | 断前尘 usage | 预测 usage | 合计金额 | 备注 |
|---|---|---|---|---|---|
| 1（test1） | 2026-09-06 | hit=94464 / miss=162545 / out=131418 = ¥0.84 | hit=9984 / miss=29891 / out=38399 = ¥0.22 | **≈¥1.06** | 首轮联调；约 23 次调用（9 分析+9 校验+5 预测） |
| 2–10 | — | — | — | — | 已按用户要求：不再跑 10 次，以 test1 这一轮结果作为成本锚 |

> self-run 要求：每次**新账号 + 新 case + 建档带经纬度**（否则缓存命中/降级会失真）。
> **实测结论**：单 case 首跑全盘成本 ≈ **¥1.06**（技术框架建议阈值 ¥0.5–1.0，实测略超上限 0.06，处于可接受边缘；`COST_GATE_MODE` 维持 `full`）。缓存复用后（同 case 再解读）边际成本极低（重复 job usage 接近 0）。
> 注意：`prompt_tokens` 按 DeepSeek 定义为「未命中输入」；若实测发现 `prompt_tokens` 实为「总输入（含缓存命中）」，需在 `scripts/cost.py` 里把 `cache_miss = prompt_tokens - cache_hit` 修正（已在脚本内注释）。

## 四、常见问题速查

| 现象 | 先查 |
|---|---|
| 页面白屏 | 浏览器 Console 报错；确认已重启后端、硬刷新加载新 index.html + regions.js |
| 建档后卡在等待页 | 看后端日志 job 是否 succeeded/failed；LLM 是否一直重试（应最多 2 次尝试） |
| 报「登录已过期」 | token 过期/缺失，重新登录 |
| 报「LLM 服务连续失败，已停止」 | 检查网络、`backend/.env` 的 key 是否有效、DeepSeek 是否限流 |
| 排盘降级（占星等缺失） | 建档是否填了经纬度（不填则 4 法降级属预期） |
