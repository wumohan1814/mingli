## 二、经验清单（按代价降序）

### A. 共享台账并发写（全天最高频坑）

**A1. 多 Session 共写同一文件 → EIO / 文件已变 / 覆盖丢失 / 撞号**
- 现象：落表与修状态全程反复报 `ReplaceFileW EIO (Win32 1175)` 与 `file changed since read`；一次"变更记录"行被并行写覆盖丢失；REQ-132 编号被并行 Session 同时占用（表内一度两条 REQ-132）。
- 根因：需求表 / Bug 表是共享单文件，主开发与需求管理 Session 同时高频写，无锁、无串行化；surgical 编辑与对方写入在同一文件上撞车。
- 规则：①动台账前先 read 锚点，用短且唯一 old_string；②撞 EIO/漂移 = 有并行写者，重读再改、不强行覆盖、不无限重试；③**EIO 报错 ≠ 没写入**，报错后重读确认是否已落盘；④关键行（编号/状态/变更记录）写后 grep 自检。
- 落地检查项：编辑后 grep 目标 ID 恰好 1 行；EIO 后重读目标行；编号唯一性审计。

**A2. 编号唯一发放（撞号 REQ-132）**
- 规则：编号由需求管理员统一发放；登记前 grep 现用最大号；冲突顺延并双向注明；审计编号唯一性。
- 落地检查项：登记前 grep max；插入后 grep 确认唯一。

### B. 状态机与口径联动（需求方两次纠正，代价高）

**B1. 口径更新 ≠ 状态更新 → 返工项停留在"待验收"**
- 现象：REQ-084 口径定稿为"返工=需要开发去做"，我一度把它置 🟡，随后并行开发实际完成重做（sprite 逐帧 + 互动元素 + 美术全量交付）转 🟠 待验收；另 REQ-135 开发已实现但状态仍 🟡。两次都是"内容/状态没联动"。
- 根因：把"内容修订"与"状态机"当两件事处理；未在登记后跟进实况（开发是否已动工）。
- 规则：**每次登记/修订同步写对状态**（🟡待开发/🔵开发中/🟠待验收/🟢已验收）；"已实现+commit"必须同步 🟡→🟠；口径演进→返工退回 🟡/🔵 注明"返工待开发"；🟠 只挂"已实现待验收"；🟢 仅测试组。**登记后要追踪实况**，不能凭"刚登记=还没开发"的假设。
- 落地检查项：落表/修状态后，用工具或 grep 对涉足条目做状态审计；与并行开发实况核对。

### C. 台账结构化（本日新增工具，方案已落地）

**C1. 纯 md 台账的痛点 → md 唯一事实源 + 派生 CSV/看板**
- 现象：需求表单元格动辄数百上千字，读得慢、状态一眼看不清；需求方提出"是否加 CSV 结合看"。
- 方案（评估后选定）：**不建第二份事实源**（双写必漂移，CSV 也装不下长文）；改为 md 仍是唯一事实源，加一个**程序生成**的派生产物：①表顶「状态一览」（按状态/模块/严重度分组清单+计数）②短字段 CSV 快照（Excel 可开、可筛选、审计用）。实现 `tools/gen_ledger_snapshot.py`（纯标准库，解析 `|` 结构，UTF-8，附带一致性校验：重复编号/空状态/未知状态 → 警告）。
- 规则：**确定性活交程序、LLM 做审计**——切字段/生成/校验由脚本完成，人/Agent 只读产物做判断；生成文件带"勿手改"标记，改源表后重跑刷新。
- 落地检查项：改台账后跑 `python tools/gen_ledger_snapshot.py`；产物有生成时间戳；警告 0 时编号唯一、状态合法。

### D. 需求方沟通（全天主线）

**D1. 先复述理解再落表（需求方硬要求）**
- 现象：需求方质疑"你确定你理解吗？开发能理解吗？"——此前基于片言+旧需求推断登记，未先复述、未点明"原始对话我没有"。
- 规则：每条需求先用自己的话复述（你要什么 → 对用户影响）→ 列疑问（带默认）→ 需求方确认 → 才落表；引用无出处历史时明说并请补充；不确定绝不硬写。
- 落地检查项：落表前有"复述 + 待确认单"；引用的历史上下文有出处。

**D2. 核实现状再登记（不凭印象）**
- 现象：用户报"某 prompt 空白/某 prompt 太长"，读盘核实发现与描述相反（空白实为 469 行、长的是另一文件）——按实测纠正并登记，无法证实处标"待复现"。
- 规则：涉及现状/数字/文件内容的登记先读源码核实；以实测为准并在备注注明"已核实"；无法定位标"待复现/待补信息"。
- 落地检查项：每条登记的证据来源标注（已核实/待复现/待确认）。

**D3. 三通道拆解 + 查重归口**
- 规则：批量口语反馈按 Bug/需求/口径变更拆解；先查重全表（含归档）再登记；已含于既有需求的归口不新增（在既有行备注"归口于 REQ-xxx"）；同主题多表象聚合、阻断/回归独立；决策让需求方拍板（带默认）。
- 落地检查项：新条目先 grep 查重；归口/聚合有备注留痕。

## 四、可复用结论

1. **台账是"单一事实源 + 单点争用"**：所有写入按"短锚点、撞写重读、EIO 复查、写后自检、编号唯一"处理，把并发写当默认前提。
2. **状态机是协作语言，必须与口径联动**："待验收"只表示已实现等验收；口径一变（含返工），状态必须跟着变，且登记后要追踪开发实况。
3. **结构化 ≠ 双份事实源**：要"看板/CSV"就用程序从唯一事实源生成派生只读产物，事实源永远只有一份。
4. **先让对方确认我理解对了，再动手/落表**：尤其涉及历史上下文时，明说"我没有这段原始描述"比脑补安全。
